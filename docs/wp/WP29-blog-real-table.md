# WP29 블로그 실제 편집기 표

## 목적과 불변 조건

상품의 표를 SmartEditor ONE의 실제 표 컴포넌트로 옮긴다. 계획의 행·열 수, 빈 셀, 각 셀의 글자·줄바꿈·굵기·링크와 주변 문단·사진 순서를 보존한다. 행 제목, 안내 문구, 값, 문장이나 임의의 빈 셀을 본문에 추가하지 않는다. 기존 일반 문단 굵기·링크 입력을 유지한다. 밴드 입력 경로는 변경하지 않는다.

## 입력·판독 설계

- 블로그 표 계획은 `rows`와 선택적인 `cellRuns`를 가진다. HTML 표 셀의 굵기·링크를 계획까지 보존한다. 출발일·가격 표는 API 배열을 그대로 사용한다.
- 기기에서 관찰한 `button[data-name="table"]`는 선택창 없이 3×3 표를 만든다. 실제 셀 컨트롤의 행·열 추가, 행·열 선택 후 셀 메뉴 삭제로 정확한 크기를 만든다. 크기 조절 손잡이와 겹치는 선택 버튼은 바깥쪽 1px 지점을 읽고 실제 히트 대조 후 누른다.
- 새 컴포넌트의 ID를 메모리에서만 보관하고 그 표의 셀만 순서대로 누른다. 기존 키보드 기반 굵기·링크 입력기를 셀 문단에 한정해 사용한다. 화면이나 선택 범위를 스크립트로 바꾸지 않는다.
- 마지막 셀 입력 뒤 실제 표를 다시 읽는다. 표 아래 기존 문단 또는 관찰한 편집기 전체 하단의 `button.se-canvas-bottom-button`을 눌러 다음 문단으로 나온다. 버튼이 없는 관찰된 편집기에서는 기본 빈 영역 입력을 사용한다. 이전 내용과 순서의 보존도 확인한다.
- 편집기와 게시 뷰어 판독은 표 한 개를 `table` 토큰 한 개로 읽는다. 셀 문단·빈 셀·굵기·편집기의 `span.se-link.__se-node[data-href]`와 뷰어의 앵커를 읽는다. 병합 셀은 단순 직사각형 표로 오인하지 않는다.
- 임시저장 재개방과 게시 페이지는 안정화 후 비교한다. 표 개수·행·열·셀 글자·셀 서식·컴포넌트 순서를 확인하며, 불일치 issue `table`의 화면 이름은 `표`다.

## 명시적 폴백

도구 없음, 크기 불일치, 셀 불일치, 커서 이탈 실패는 고정 사유로 구별한다. 이번 삽입으로 생긴 유일한 표만 전체 셀 선택→삭제로 없애고 원래 문서가 그대로임을 읽어 확인한 뒤 기존 ` | ` 텍스트 행으로 옮긴다. 셀 서식은 행 안에서도 유지한다. 제거 확인이 안 되면 저장 전에 멈춘다. 임시로 채운 표는 저장하지 않는다.

WP20 로그에 `table_insert_started`, `table_size`, `cells_filled`, `table_verified` 또는 `table_fallback`을 남긴다. 허용 필드는 숫자 행·열·셀 수와 고정 사유뿐이다. 셀 글자·상품 문구·식별자·주소는 기록하지 않는다. 결과 화면과 재시작 뒤 등록 기록에도 “표를 넣지 못해 같은 내용을 글자 행으로 옮겼습니다.”를 표시한다.

미리보기는 기존 초록·가는 선 스타일의 실제 HTML 표로 표시한다. 첫 행을 임의로 제목/굵게 처리하지 않으며 셀의 원래 굵기·링크·줄바꿈을 표시한다.

## 검증과 기기 한도

합성 자료로 모델, 셀 서식, 크기 조절, 순서, 임시저장 재개방, 게시 페이지 지연 표, 명시적 폴백, 제거 실패 시 저장 금지, 미리보기, 로그 허용 필드·재시작 이력을 시험한다. 전체 설치는 WP28 설치 게이트를 사용한다. 같은 깨끗한 커밋에서 의존성 설치·전체 시험·타입 검사·빌드·APK 내부 내장 엔진 호환성을 통과한 APK만 `adb install -r`로 설치한다.

실제 공개 발행 클릭 0회, 밴드 동작 0회. 실제 임시저장 최대 2회, 첫 저장에 결함이 있을 때만 회귀시험·수정·게이트 재설치 후 두 번째를 사용한다. 2026-11-17 21:00 KST 이후에는 새 임시저장을 시작하지 않고 21:30까지 끝낸다. 기존 주인 글과 임시글은 손대지 않는다. 저장소 밖 `../runs/blog-shots/wp29-summary.txt`에 사용량과 확인 상태를 계속 기록한다.
