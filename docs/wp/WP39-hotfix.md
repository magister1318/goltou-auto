# WP39 골투오토 1.0.6 핫픽스

`codex/v105`의 `c174085`에서 보고된 1.0.5 실기기 등록 결과를 기준으로 한다. 작업 한 건에 블로그 한 곳과 밴드 두 곳이 있었고, 사진 66장과 본문 20문단을 입력했다. 블로그와 밴드 한 곳은 게시 주소를 받았고, 나머지 밴드는 작성기를 열지 못했다.

| 항목 | 변경 및 회귀 시험 |
| --- | --- |
| A | 네이버와 밴드의 게시 본문에 속한 사진 자리를 순서대로 센다. 빈 `src`, 지연 로딩 주소, 대체 이미지와 사진 자리만 있는 경우를 재현한다. 편집기에서는 사진 자리를 읽고, 저장 전에 원본 파일과 업로드 결과를 대조한다. |
| B | 네이버 본문과 별도의 태그 영역을 확인한다. 비공개 글에서 태그 영역을 읽을 수 없으면 게시 주소를 유지하고 결과에 태그 확인이 필요하다고 표시한다. 이미지 로딩용 클릭과 키 입력을 제거한다. 재열기 중 자동저장 차단은 유지하고 해당 차단을 예상 이벤트로 기록한다. |
| C | 밴드 상세를 쓰기 화면과 별도의 읽기 전용 WebView에서 확인한다. 같은 주소의 데스크톱 상세를 읽을 수 없으면 모바일 상세를 한 번 읽는다. 게시 주소가 있으면 게시 결과로 기록하고, 판독 수와 확인된 누락을 결과에 덧붙인다. |
| D | 밴드 세션, 게시판 목록 응답, 글쓰기 버튼, 작성기 대기에 각각 이름을 붙인다. 대상 밴드는 숫자 키로 확인한다. 글쓰기 권한 안내, 버튼이 보이나 작성기가 열리지 않는 경우, 작성기 DOM 변형을 재현한다. 타임아웃에는 제한 시간, 제어 요소 개수, 식별자를 가린 경로를 기록한다. |
| E | 내 등록 기록의 유효한 게시 주소로 삭제를 시작할 수 있게 한다. 현 상품 제목·본문으로 재생성하지 않는다. 해당 서비스에서 글의 주소와 소유 제어를 검증한 뒤 사용자가 확인한 한 글의 삭제 요청만 허용한다. 삭제 응답과 재조회 확인 뒤에 기록을 갱신한다. |
| F | 기기에서는 전체 로그를 계속 남긴다. 전송본에서 성공한 CDP·네이티브·가로채기 호출을 건수와 합계·최대 시간으로 집계한다. 실패와 중요한 단계는 유지하고, 전송 한도를 넘으면 앞뒤와 중간 생략 표시를 남긴다. |
| G–I | 다운로드 전부터 계획의 사진 수를 사용하고 UI에 완료 수/전체 수를 표시한다. 상품 첫 페이지 요청은 실패 후 350ms에 한 번 다시 요청한다. Android 버전은 1.0.6 (10)이다. |

가격·출발일 숫자, 링크, 문단 및 사진 누락은 저장 전 대조한다. 본문 전달은 기존 입력 방식과 원문을 따른다. 게시 뒤에는 확인한 주소와 상세 판독 결과를 함께 표시해 같은 글을 중복 게시하지 않도록 한다.

합성 페이지와 로컬 재현에서 검증한다. 전체 테스트, 타입 검사, Node 18 내장 런타임 호환성 검사, Android 디버그 빌드를 수행한다. 실계정 발행·삭제, 실기기 설치, 서명 릴리스 작업은 이번 작업에 포함하지 않는다.
