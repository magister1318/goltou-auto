# WP7 운영 API 연결과 실제 상품 변환 점검

브랜치 `codex/wp7-real-api` (main에서 시작), 초안 PR 대상 main. 보고서 `docs/reports/WP7.md`.

## 배경

- 골투 운영 서버에 `/auto` API가 반영됐습니다(2026-11-13). 주소는 `https://api.goltou.kr`, 계약은 `docs/api-contract.md`.
- 지금 앱(`apps/android/bridge/main.ts`)은 `createFakeApi`와 가짜 매니저 세션으로 돕니다. 이것을 실제 로그인과 실제 API로 바꿉니다.
- 변환기(WP4)는 합성 예시로만 검증됐습니다. 실제 상품 본문에서 어떤 구조가 나오는지 수치로 확인합니다.

## 할 일

1. **실제 API 연결**: 앱 기본 동작을 `createApiClient('https://api.goltou.kr', fetch)`로 바꿉니다. 주소는 빌드 설정 한 곳에서만 정합니다. 가짜 API는 시험과 디버그 빌드의 명시적 실험 화면에서만 남깁니다. 릴리스 경로에 가짜 계정·가짜 세션이 섞이지 않게 합니다.
2. **로그인**: WP3 로그인 화면에서 사용자가 직접 넣은 아이디·비밀번호를 `/auto/login`으로 한 번 보내고, 받은 토큰만 보관합니다. 비밀번호는 메모리에서도 요청 뒤 바로 버리고 어디에도 저장·로그하지 않습니다. 토큰은 Android Keystore로 암호화한 저장소에 두고, `auth`·`forbidden` 응답이면 지우고 로그인 화면으로 보냅니다. 로그아웃은 `/auto/logout` 뒤 토큰 삭제. `device`에는 kind `android`, 기기 모델, 앱 버전만 넣습니다.
3. **오류 처리**: 네트워크 끊김·시간 초과(요청당 15초)·`server`는 화면에 한국어 문장으로 보여 주고 같은 요청을 자동 반복하지 않습니다(목록 새로고침은 사용자가 누를 때만). `/auto/posts/start`·`update`는 중복 호출 금지 원칙을 유지합니다.
4. **상품 사진 내려받기**: 준비 단계의 사진 URL이 실제 골투 주소(`api.goltou.kr` 이미지 경로 등)일 때 동작하는지 확인합니다. 허용 호스트는 goltou.kr 계열만, 그 밖의 호스트 사진은 준비 실패로 처리하고 이유를 보여 줍니다.
5. **변환 점검 도구(디버그 빌드 전용)**: 실험 화면에 `변환 점검` 버튼. 로그인한 세션으로 상품 목록을 최신순으로 최대 60개(요청 사이 1초 이상 간격) 읽어 각각 블로그·밴드 `InputPlan`을 만들고, 등록·사이트 열기는 하지 않습니다. 결과 파일에는 상품 번호와 수치만 남깁니다: 블록 종류별 개수, 표 개수와 표 안 사진 여부, 사진 수, 지원하지 않아 글자로 떨어뜨린 요소 종류, 변환 실패 코드, 본문 글자 수, 밴드 글자·사진 한도 초과 여부, 원문 대비 숫자(가격·날짜) 보존 대조 결과. 상품 본문 글·제목·사진 주소는 결과 파일과 저장소에 넣지 않습니다.
6. **시험**: 실제 API 클라이언트 경로를 로컬 가짜 HTTP 서버(계약 응답)로 시험합니다. 토큰 만료·forbidden·네트워크 오류·시간 초과·로그아웃, 릴리스 구성에 가짜 API가 없다는 것, 변환 점검 결과에 본문이 없다는 것.

## 실기기(SM-S928N) 단계

- 새 APK 설치 뒤 앱을 로그인 화면까지만 엽니다. **골투 로그인은 사용자가 폰에서 직접 합니다.** 아이디·비밀번호를 대신 넣거나 화면에서 읽지 않습니다. 로그인 전이면 여기서 멈추고 보고서에 `사용자 로그인 대기`로 적고 끝냅니다(대기 반복 금지).
- 로그인돼 있으면: 실제 상품 목록 표시 → 변환 점검 60개 실행 → 결과 수치를 보고서 표로. 그다음 실제 상품 1개(사진 3~8장인 것)로 블로그 임시저장 1회만 해 보고 재열람 대조 결과를 적습니다. 제목은 원 제목 앞에 `[골투오토 실험] `을 붙입니다. 밴드는 이번에 하지 않습니다.
- 실제 발행·밴드 게시 금지, 네이버 임시저장은 이번 실행에서 최대 1건, 폰에서 `kr.goltou.auto` 밖은 건드리지 않고 잠금 해제·깨우기 금지, 화면이 꺼져 있거나 앱이 앞에 없으면 실기기 단계 생략. 운영 API에는 읽기와 이 앱의 정상 기록(`posts/start`·`update`)만, 부하를 주는 반복 호출 금지.
