# WP8 사진 많은 상품과 밴드 한도

브랜치 `codex/wp8-heavy-photos` (main에서 시작), 초안 PR 대상 main. 보고서 `docs/reports/WP8.md`.

## 배경

실제 상품 60개 점검에서 상품당 사진이 최소 4장, 중앙값 32.5장, 최대 69장이었습니다. 지금까지 실기기 확인은 사진 8~12장 상품뿐입니다. 사진이 많은 상품에서 시간·안정성·밴드 한도가 어떻게 되는지 수치로 확인하고, 부족한 부분을 고칩니다.

## 할 일

1. **블로그, 사진 많은 상품**: 사진 30~40장인 실제 상품 1개로 임시저장을 끝까지 실행합니다(앱 혼자 완료, 재열람 대조 포함). 단계별 시간, 사진 한 장당 평균 올리기 시간, 실패·재시도 여부, 재열람 때 지연 로딩 사진을 모두 읽는 데 걸린 시간을 기록합니다. 문제가 있으면 원인을 고치고 한 번 더 확인합니다.
2. **진행 표시**: 사진이 많을 때 사용자가 멈춘 것으로 오해하지 않도록 실행 화면에 `사진 n/N`과 남은 예상 시간(관측한 장당 시간 기준, 처음 3장 뒤부터 표시)을 보여 줍니다. 예상 시간은 추정이라고 표시합니다.
3. **밴드 한도 관측**: 같은 상품(또는 사진 30장 이상인 다른 상품)으로 밴드 임시저장 방식(게시 전 멈춤)을 실행해, 밴드가 알려 주는 사진 한도와 글자 한도를 관측값으로 기록합니다. 한도를 넘으면 지금 동작(입력 전에 막고 이유 표시)이 실제 화면에서 맞게 나오는지 확인합니다. 사진을 임의로 자르거나 나누지 않습니다. 끝나면 `버리기`로 작성 내용을 없애고 남은 글이 없는지 확인합니다.
4. **한도 초과 대안 조사(구현하지 않음)**: 밴드 한도를 넘는 상품이 60개 점검 결과 기준으로 몇 개인지 세고, 가능한 방식(앞에서부터 한도까지만, 사용자가 사진 고르기, 여러 글로 나누기)의 장단점을 보고서에 짧게 적습니다. 결정은 사용자가 합니다.
5. **취소선 글자 수치**: `del`/`s`/`strike` 안의 글자가 숫자(가격·날짜)를 포함하는 상품이 60개 중 몇 개인지 변환 점검 도구에 지표를 추가해 셉니다(본문은 남기지 않음). 처리 방식은 사용자 결정 전까지 바꾸지 않습니다.

## 실기기 규칙

지금까지와 같습니다. 화면 켜짐·앱 전면을 읽기 전용 두 신호로 확인, 깨우기·잠금 해제 금지, 골투·네이버·밴드 자격 증명 입력 금지, `kr.goltou.auto` 밖은 건드리지 않음. 실제 발행·밴드 게시 금지(밴드는 게시 전 멈춤 뒤 버리기). 네이버 임시저장은 이번 실행에서 최대 2건, 밴드 작성기 열기는 최대 3회. 앱이 남긴 작성 내용의 자동복구 안내는 사용자 상시 허락에 따라 앱의 `버리고 새로 시작`을 눌러도 됩니다. 제목에는 `[골투오토 실험] ` 접두사. 운영 API에는 정상 읽기와 앱의 정상 기록만.

## 지키는 것

AGENTS.md의 원칙 전부. 임시저장 방식의 발행 방지 3중 장치(초점 확인, 레이어 닫힘 확인, 발행 요청 차단)를 약화시키지 않습니다. 상품 제목·본문·사진 주소·계정 정보는 저장소·보고서에 남기지 않습니다. GitHub는 `gh`와 `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`만. typecheck·전체 시험·Android 빌드 결과와 함께 초안 PR을 올립니다.
