# WP3. 앱 화면 (B안)과 골투 API 클라이언트

브랜치 `codex/wp3-ui`. **`codex/wp1-android-shell`에서 갈라 나옵니다**(WP1이 아직 main에 합쳐지지 않았습니다). 초안 PR의 대상도 `codex/wp1-android-shell`로 엽니다. 먼저 `AGENTS.md`, `docs/PRD.md`, `docs/design/README.md`, `docs/design/mockups/B_*.dc.html`, `docs/api-contract.md`를 읽습니다.

## 목표

시안 B안과 같은 화면을 실제로 누를 수 있게 만듭니다. 골투 서버와 실제 블로그·밴드 등록은 아직 붙이지 않고, 가짜 데이터로 모든 화면과 상태를 볼 수 있어야 합니다. 등록 엔진(WP4~6)이 나중에 그대로 끼워질 수 있도록 경계를 정합니다.

## 할 일

1. `packages/api-client`
   - `docs/api-contract.md`의 모든 경로에 대한 타입과 클라이언트(`fetch` 주입식, 토큰 보관은 호출자가 넘김). 오류는 `code`를 가진 예외 하나로.
   - 같은 인터페이스의 가짜 구현(메모리 안 예시 상품 12개 이상, 기록, 설정, 등급 3종 계정). 화면 개발과 시험에 씁니다.
   - 단위 시험: 봉투 처리, 오류 코드, 토큰 머리글.
2. `packages/core`
   - 화면과 주고받는 메시지 약속을 `packages/core/src/protocol.ts`에 타입으로 정리합니다: 골투 로그인/로그아웃, 상품 목록·상세, 기록 목록, 설정, 서비스 로그인 상태(네이버·밴드·AI: 확인됨 / 풀림 / 모름), 서비스 로그인 화면 보이기·숨기기, 등록 작업 시작·멈춤·이어하기, 작업 진행 알림.
   - 등록 작업 상태 모델: 한 번에 한 작업만. 단계 목록(사진 내려받기, 본문 정리, 블로그에 쓰기, 밴드에 쓰기 등), 현재 단계, 단계 안 진행(예: 사진 3/5), 상태(진행 / 로그인 풀림으로 멈춤 / 사용자가 멈춤 / 실패 / 임시저장됨 / 발행됨).
   - 이번에는 **가짜 등록 실행기**만 넣습니다: 시간에 따라 단계를 넘기고, 설정에 따라 '로그인 풀림'과 '실패'를 재현할 수 있어야 합니다. 실제 사이트는 열지 않습니다. 진짜 실행기가 같은 인터페이스로 바꿔 끼워지게 합니다.
   - 골투 토큰은 core가 보관합니다(화면 쪽 저장소에 두지 않음). 보관 방식은 지금은 메모리, 영구 보관은 껍데기 채널이 필요하므로 인터페이스만 두고 보고서에 남깁니다.
   - WP1의 진단 기능은 설정 화면 아래 '진단'으로 옮겨 유지합니다.
3. `packages/ui` 화면 (문구·크기·색은 시안 그대로)
   - 골투 로그인(시안 없음, 같은 토큰으로). 일반 회원(0~2)은 안내 문구와 함께 막힘.
   - 홈: 머리 부분, 로그인 상태 3개 줄(누르면 그 서비스 로그인 화면 열기 요청), 검색, 탭(전체 / 안 올린 상품 / 출발 월), 상품 목록(무한 스크롤 또는 더 보기), 아래 탭(상품 / 등록 기록).
   - 옮길 내용 확인: 블로그용/밴드용 전환, 원문 대조 줄, 등록 방식(임시저장 기본 / 발행), 올릴 곳 스위치, 선택 옵션(문장 다듬기, 끝 문구, 링크 카드, 모두 기본 꺼짐), 아래 실행 막대. 발행을 고르면 실행 전에 한 번 더 확인합니다.
   - 등록 진행: 큰 단계 숫자, 진행 막대, 세로 단계 목록, 멈추기.
   - 로그인이 풀렸을 때: 보관된 단계, 서비스 로그인 화면이 열릴 자리, '로그인했어요, 이어하기', '나중에 하기'.
   - 등록 기록: 내 기록 / 전체(직원·관리자만 보임), 채널별 결과와 다음 행동(확인하고 발행, 주소 복사, 다시 시도), '등록 뒤에 상품이 바뀌었습니다' 표시.
   - 설정(시안 없음): 내 계정·로그아웃, 서비스별 로그인 지우기, 관리자만 끝 문구·기본 해시태그·밴드 하루 한도 저장, 진단.
   - 공통: 카드·그림자·테두리 상자·왼쪽 색 띠·이모지 금지. 누르는 영역 44px 이상. 색만으로 상태를 구분하지 않기. 글자 크기를 키워도 깨지지 않기. 뒤로 가기(안드로이드 뒤로 버튼 포함)가 화면 순서대로 동작.
   - 상태 관리는 가볍게(React 상태와 작은 저장소 하나). 화면 전환 라이브러리는 꼭 필요할 때만.
4. `pnpm sim`
   - 가짜 API와 가짜 실행기로 앱 전체가 PC에서 뜹니다. 390×844 화면으로 아래 장면을 `docs/reports/wp3/`에 PNG로 저장하는 스크립트(`pnpm sim:shots`)를 만듭니다: 로그인, 홈(전체), 홈(안 올린 상품), 확인(블로그), 확인(밴드), 진행 중, 로그인 풀림, 기록(내 기록), 기록(전체), 설정(관리자), 일반 회원 막힘. PNG는 커밋합니다(검토용, 장당 300KB 이하).
5. 시험: api-client 단위 시험, 가짜 실행기의 상태 전이(멈춤·이어하기·실패·로그인 풀림), 화면은 주요 흐름 한 줄기(로그인 → 상품 고르기 → 임시저장 실행 → 완료 → 기록)를 시뮬레이션으로 확인.

## 하지 않는 것

실제 골투 서버 연결, 실제 네이버·밴드·구글 화면 열기, 본문 변환, 사진 내려받기, 안드로이드 Kotlin 변경(뒤로 버튼 전달에 꼭 필요한 한두 줄은 가능, 보고서에 적기), 새 디자인 요소 추가.

## 끝내는 기준

- `pnpm install && pnpm typecheck && pnpm test` 통과, `pnpm sim:shots` 가 위 장면을 모두 저장.
- `apps/android`에서 `./gradlew assembleDebug` 성공(실기기 실행은 하지 않음. 보고서에 '실기기 미확인').
- 시안 B안 5개 화면과 나란히 놓고 볼 때 구성, 문구, 색, 여백이 같음. 다른 곳은 보고서에 이유와 함께 적기.
- `docs/reports/WP3.md` 작성, 초안 PR.
