# WP20: 영구 작업 로그, 밴드 왕복 시험, 실제 모습의 미리보기

## 목적과 소유자 지시

2026-11-16 23:00 KST 소유자 지시 원문:

> 네이버 블로그와 밴드 등록에 로그를 기록해서 향후에도 깜깜이 개발은 방지했으면 합니다. 각 과정을 로그로 기록하지 않으면 결국 깜깜이 개발을 할 수밖에 없습니다. 깜깜이 개발을 한다는건 향후 유지보수를 포기한다는것과 다름없습니다.

생성·읽기·삭제 요청을 앱의 차단기가 거절한 이유를 임시 진단 없이는 설명하지 못했던 문제를 해결한다. 등록 과정의 근거를 항상 남기는 것이 핵심이다.

이번 작업은 `codex/band-real-test`에서 만든 `codex/job-logs`에서 한다. PR #23이 열려 있으면 해당 브랜치를, 병합됐으면 `main`을 대상으로 초안 PR을 연다. 이 지시의 브랜치·밴드 시험 승인이 일반 작업 규칙보다 우선한다.

## A. 항상 켜진 영구 로그

- 디버그·릴리스 모두 블로그 임시저장/발행/글 삭제, 미완료 글 정리, 밴드 게시/글 삭제, 로그인 확인, 밴드 목록 읽기를 작업별로 기록한다. 앱 전용 `files/logs/yyyyMMdd/time-kind-jobId.jsonl`과 작은 색인을 쓴다.
- 각 줄은 밀리초 시각, 임의 작업 ID, 사이트, 단계, 이벤트(start/ok/fail/retry/skip/wait), 소요 시간, 고정 실패 사유, 문단·사진 위치/전체 수·바이트·실행 횟수를 포함한다. 요청 차단 결정에는 메서드, 호스트, 식별값을 제거한 경로, 콘텐츠 유형, 쿼리/본문 **필드 이름만**, 허용/차단과 고정 사유를 남긴다.
- 이동은 호스트와 식별값 없는 경로만, 확인창은 종류만, 선택자 누락은 고정 선택자 이름만 남긴다. 검증은 예상/실제 개수와 실패 항목, 실행 환경은 앱 버전·커밋·WebView 버전·기기 모델을 남긴다.
- 비밀번호·쿠키·토큰·인증 헤더·계정 식별자/이름·밴드 이름/번호·블로그 ID·글 주소/번호·상품/제목 문구·사진 내용을 기록하지 않는다. 연관 확인에는 앱 전용 소금을 사용한 짧은 해시만 쓴다. 로그 API는 허용 필드·열거 코드만 받으며, 비밀처럼 보이는 값과 콘텐츠가 출력되지 않는 자동 시험을 둔다.
- 실행기, 글 삭제, 요청 차단기, surface/CDP, native bridge의 단계 경계·재시도·조기 반환·예외를 남긴다. 작업 종료 줄은 succeeded / failed:사유 / stopped:사유 / uncertain:사유 중 정확히 하나다. 각 종류의 가짜 편집기 성공 경로와 각 단계 실패 주입에서 순서·종료 줄을 검증한다. 실제 네이버를 조작하지 않는다.
- 각 줄을 즉시 추가하고 flush한다. 다음 실행 시 종료 줄 없는 작업에 interrupted 복구 종료 줄을 추가한다. 30일 또는 50MB 중 먼저 도달한 한도를 적용해 오래된 것부터 지운다. 서버 업로드는 없다.
- 디버그 PC 추출: `scripts/pull-logs.ps1`에서 `adb shell run-as kr.goltou.auto`를 사용해 외부 `../runs/logs/`로 가져온다.
- 앱 설정에 ‘작업 로그’ 한 행과 단순 목록 화면을 둔다. 최근 작업의 시간·종류·결과·실패 단계와 사람이 이해하는 한국어 사유를 표시한다. ‘로그 내보내기’는 공유 가능한 캐시 ZIP을 만들어 Android 공유창을 연다. 릴리스에서도 제공한다.
- 실패/확인 필요 등록 기록에도 실패 단계와 코드에서 유도한 한국어 사유를 표시한다. 기존 임시 차단·삭제 진단 파일의 역할은 이 로그로 통합한다.

## B. 승인된 밴드 왕복 시험 한 번

2026-11-17 00:31 KST 결정 카드에서 승인한 동일 밴드의 야간 확인 글 한 건과 앱 삭제만 수행한다. 실제 대상 이름·ID·URL·상품 문구는 저장소에 넣지 않는다. 다른 밴드를 고르지 않으며 기존 18:14 블로그 임시글과 같은 첫 판매 중 상품을 사용한다.

1. 기기 켜짐·잠금 해제·앱 포커스 가능 여부를 읽기만 한다. 깨우기/잠금 해제/설정 변경/다른 앱 조작을 하지 않는다. 사용할 수 없으면 B를 건너뛰고 C를 계속한다. 설치는 `adb install -r`만 한다.
2. 공유 밴드 프로필을 쓰는 앱의 밴드 WebView에서 같은 시험 제목의 잔여 글이 없는지 먼저 확인한다.
3. 앱이 계획한 내용을 그대로 쓴다. 일회 허용 파일은 제출 직전에 한 번 만들며, 실제 제출 클릭은 정확히 한 번만 한다. 차단/불확실이면 재제출하지 않고 읽기로 확인한 뒤 시험으로 수정한다.
4. 새 로그로 앱 자체 성공·즉시 주소가 저장된 기록·게시됨 결과·계획과 실제 본문/줄바꿈 158개/사진 29장 순서/태그 2개/링크 2개를 입증한다. 복구로 성공을 대신하지 않는다.
5. 등록 기록 → 밴드 글 삭제 → 확인으로 첫 삭제를 시도한다. 피드와 원래 주소에서 부재를 확인하고 ‘삭제됨’(앱 삭제 상태)을 확인한다. 첫 삭제 실패면 동일 앱 생성 글의 신원이 입증된 경우에만 수정·삭제 재시도를 06:00 KST까지 계속한다. 새 글을 만들지 않는다. 06:00에도 남아 있으면 최종 답변 첫 줄에 알린다.
6. 앱만 adb 캡처해 외부 `../runs/band-shots/i-*.png`로 남긴다. 살균한 실제 게시·삭제 로그 예시는 `wp20-sample-log.txt`에 남긴다. 실제 시험을 못 했으면 예시를 조작하지 않는다.

## C. 밴드 미리보기

전체 글은 원래 텍스트 뒤에 사진을 한 장씩 가로 전체 폭으로 세로 쌓고 태그·URL은 링크 모양으로 표시한다. ‘목록에서는 이렇게 보입니다’ 표본은 약 115자와 더보기, 사진 3칸과 남은 수 겹침 표시를 사용한다. 본문 문구는 더하거나 빼거나 바꾸지 않는다. 가짜 편집기·시험·디자인 참고를 갱신하고 기기에서 `i-preview-*.png`로 확인한다.
