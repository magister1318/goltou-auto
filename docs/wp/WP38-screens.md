# WP38 골투오토 1.0.5 화면

`codex/v105`의 WP37 엔진 위에 `../refs/ux-v4-design.html`의 승인된 4차 시안을 적용한다. `../runs/v105-contract.md`의 선택 필드는 구서버에서 없어도 화면을 이용할 수 있게 처리한다.

1. 상품 이름과 사진을 누르면 상세를 열고, 올리기는 목록에서 발행 창을 연다. 담당자와 내 블로그·밴드 상태를 보여 주고 안 올린 상품 필터는 내 등록 기록을 기준으로 유지한다.
2. 상세에는 상품을 올린 사람, 글 보기, 변경 안내, 종류가 표시된 태그를 배치한다. 블로그·밴드 미리보기는 앞·끝 문구가 들어갈 위치를 표시하고 밴드는 마지막 태그 줄을 보여 준다.
3. 발행 창은 이전 게시 내역을 안내하고 마지막 밴드 선택을 되살린다. 밴드를 여러 곳 고를 수 있으며 3일 이내 같은 밴드의 게시 내역은 안내로 표시한다. 오늘 사용량에 따른 한도, 이번 작업의 끝 문구, 공개 범위와 최종 확인을 연결한다. 블로그 임시저장은 유지한다.
4. 등록 진행에 대상별 상태와 현재 밴드의 순번, 밴드 사이 대기를 표시한다.
5. 결과에 확인된 게시 수와 대상별 상세를 표시한다. 재시도 대상은 확정 실패로 제한한다.
6. 설정에서 내 글 앞·끝 문구, 회원 정보 치환 미리보기, 끝 문구 기본 스위치를 편집하고 저장한다. 공통 설정에는 태그로 붙일 정해 둔 글자와 밴드 한도를 표시한다.
7. 홈에서 뒤로 누르면 2초 동안 하단에 안내를 표시한다. 그 안에 뒤로 한 번 더 누르면 앱 종료 확인을 표시한다. 진행 중인 작업은 종료에 앞서 멈춘다. Android 로그에는 종료 흐름의 단계만 남긴다.
8. 관리자 등록 기록 상단에서 오늘 현황을 읽어 표시한다. 경로가 없는 구서버에서는 이 부분을 생략한다.

컴포넌트 시험과 전체 스위트, 타입 검사, Android 디버그 빌드를 실행한다. 가짜 API로 360·412 화면 폭에서 화면을 확인하고 이미지를 `../runs/wp38-shots/`에 저장한다. 작업 보고서는 `../runs/wp38-report.md`에 남긴다.

캡처 재현 명령은 저장소 루트에서 실행한다.

```powershell
node scripts/build-core.mjs --out tmp/wp38-ui
node scripts/simulate-wp38.mjs
```
