# WP4. 상품 변환, 원문 대조, 문장 다듬기(AI Mode)

브랜치 `codex/wp4-convert`. **`codex/wp0-device`에서 갈라 나옵니다**(WP0 PR #3이 아직 main에 없습니다). 초안 PR 대상도 `codex/wp0-device`. 먼저 `AGENTS.md`, `docs/PRD.md`, `docs/api-contract.md`, `docs/reports/WP0.md`(특히 3단계 결과와 권고)를 읽습니다.

## 목표

골투 상품 하나(`/auto/products/get` 응답)를 블로그용 글과 밴드용 글로 바꾸는, 사이트와 무관한 변환 단계를 만듭니다. 사이트에 입력하는 일은 WP5·WP6입니다.

## 확정된 규칙

- 기본은 **원문 그대로**입니다. 글자를 고치거나 빼거나 더하지 않습니다. 문장 다듬기는 사용자가 켰을 때만.
- 가격, 출발일, 골프장 이름, 상품 주소는 API 값만 씁니다. AI 응답의 숫자를 본문에 쓰지 않습니다.
- 사진은 원본 주소를 그대로 내려받습니다(크기 줄이기·형식 바꾸기 금지).
- 밴드는 임시저장이 없으므로 임시저장 모드에서는 '게시 전 멈춤'입니다(WP6에서 구현, 여기서는 상태 이름만 `protocol.ts`에 추가: `stopped_before_post`).

## 할 일

1. `packages/core/src/convert/`
   - 상품 HTML(`contentsHtml`) → **블록 목록**: 문단(글자와 굵게·줄바꿈 정도의 최소 서식), 사진(원본 주소, 순서), 표(행·열 글자), 구분선, 링크. 원문에서의 순서를 지킵니다. 스크립트·스타일·추적 코드·빈 문단은 버리되 버린 것을 기록합니다.
   - HTML 파서는 Node 18에서 도는 가벼운 것(예: parse5 또는 htmlparser2). 브라우저 DOM에 기대지 않습니다.
   - 블로그용 조립: 제목, 대표 사진들, 본문 블록, 출발일·가격 표(API의 `departures`), 골프장 목록, (옵션이 켜졌을 때만) 끝 문구, 골투 링크 카드용 주소, 해시태그.
   - 밴드용 조립: 같은 내용을 글자 위주로(표는 줄 목록으로), 사진은 순서대로 묶음. 밴드에서 못 쓰는 서식은 글자로 풉니다.
   - 조립 결과는 '입력 계획'입니다: 순서 있는 단계(글자 입력 / 줄바꿈 / 사진 n장 첨부 / 표 입력)의 목록. WP0에서 확인했듯 사진은 원문 위치에 맞춰 커서 자리마다 나눠 넣을 수 있어야 합니다.
2. `packages/core/src/verify/` 원문 대조
   - 변환 전후 비교: 공백을 정리한 글자 수, 문단 수, 사진 수와 순서, 가격 개수와 값, 출발일 개수와 값, 골프장 이름. 다르면 무엇이 다른지 항목으로 돌려줍니다.
   - 화면의 '원문과 일치합니다. 가격 6, 출발일 6, 사진 5' 줄이 이 결과를 씁니다. 불일치가 있으면 실행 막대를 막고 이유를 보여 줍니다.
   - 같은 비교 함수를 WP5·WP6이 '저장 뒤 다시 읽은 값'에도 쓸 수 있게 입력을 일반화합니다.
3. 사진 내려받기 `packages/core/src/media/`
   - 원본 주소에서 내려받아 앱 전용 임시 폴더에 두고(껍데기가 주는 경로, 인터페이스로 받음) 작업이 끝나면 지웁니다. 크기·형식은 건드리지 않습니다. 실패한 사진은 건너뛰지 않고 작업을 멈춥니다.
   - 내려받기 주소는 http/https, 그리고 API가 준 주소만 허용합니다. 시험은 로컬 서버로.
4. 문장 다듬기 `packages/core/src/polish/` + `packages/sites/ai-mode/`
   - `../refs/DAF`의 AI Mode 엔진을 읽고 필요한 만큼만 옮깁니다. AI 세션(`goltou-ai`)의 숨김 Surface에서 구글 AI Mode에 문단 묶음을 보내고 답을 읽습니다. 입력은 입력 명령으로만.
   - 지시문: 뜻과 사실을 바꾸지 말고 문장만 자연스럽게, 숫자·날짜·고유명사·주소는 그대로, 문단 수 유지, 꾸밈말과 광고 문구 추가 금지, 문단마다 번호를 붙여 돌려주기.
   - **검증기**: 다듬은 문단마다 원문의 숫자·날짜·금액·골프장 이름·주소가 모두 그대로 있는지, 새 숫자가 생기지 않았는지, 길이가 원문의 70~130%인지 확인합니다. 하나라도 어기면 그 문단은 원문을 씁니다. 표, 가격·출발일 줄은 AI에 보내지 않습니다.
   - AI Mode가 안 열리거나, 로그인을 요구하거나, 답이 형식에 안 맞으면 다듬기 없이 원문으로 진행하고 사용자에게 알립니다(작업을 실패로 만들지 않음).
   - 화면: 확인 화면에서 다듬기를 켜면 문단별로 원문/다듬은 글을 나란히 보고 문단마다 되돌릴 수 있게 합니다(B안 토큰, 새 디자인 요소 없이).
5. 가짜 실행기 대신 쓸 실제 '준비 단계'(사진 내려받기, 본문 정리)를 등록 작업의 첫 두 단계로 연결합니다. 사이트 입력 단계는 아직 가짜입니다.
6. 시험
   - 예시 상품 HTML 8개 이상을 `packages/core/test/fixtures/`에 만듭니다(실제 운영 데이터 아님): 표 있는 글, 사진만 있는 글, 사진 사이에 글이 섞인 글, 붙여넣기 흔적이 많은 지저분한 HTML, 아주 긴 글, 빈 문단투성이, 링크·굵은 글씨, 깨진 태그.
   - 변환 → 대조가 모두 일치로 나오는지, 일부러 숫자를 바꾼 경우를 대조와 다듬기 검증기가 잡는지.
   - AI Mode는 로컬 가짜 페이지로 단위 시험. 실기기에서는 실험 화면에 'AI 다듬기 실험' 하나를 추가해 예시 문단 3개로 한 번만 돌려 봅니다(구글 로그인은 하지 않습니다. 로그인을 요구하면 멈추고 보고).

## 하지 않는 것

실제 골투 서버 연결, 네이버·밴드 편집기 입력, 발행·게시, 사진 크기 변경, 운영 데이터 사용.

## 끝내는 기준

- `pnpm install && pnpm typecheck && pnpm test`, `./gradlew assembleDebug` 통과. 폰이 연결되어 있으면 새 APK 설치와 AI 다듬기 실험 1회(폰에서는 `kr.goltou.auto` 밖을 건드리지 않음. 화면에 확인창이 떠 있으면 건드리지 말고 보고).
- `docs/reports/WP4.md`: 예시별 변환·대조 결과 표, AI Mode 실기기 결과(됨 / 안 됨 / 로그인 요구), 걸린 시간, 남은 문제. 초안 PR.
