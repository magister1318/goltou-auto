# 작업 로그 사용

디버그·릴리스 모두 앱 전용 `files/logs/`에 작업별 JSONL과 `index.json`을 보관한다. 서버로 보내지 않는다. 한 줄을 추가할 때마다 파일을 동기화하며, 종료 줄이 없는 작업은 다음 실행 때 `interrupted`로 복구한다. 완료된 오래된 작업부터 30일/50MB 보존 한도를 적용한다.

설정 → 작업 로그에서 시간·작업 종류·결과·실패 단계를 확인한다. 실패/확인 필요에는 고정 사유를 한국어 문장으로 보여준다. 로그 내보내기를 누르면 공유용 캐시에 ZIP을 만들고 Android 공유창을 연다. ZIP에는 작업 파일과 색인만 들어가며 인증 파일과 상관관계 해시의 소금은 넣지 않는다. 릴리스에서 `run-as`가 불가능해도 이 기능을 사용할 수 있다.

디버그 기기를 PC에 연결한 뒤 저장소 루트에서 다음을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/pull-logs.ps1
```

기본 목적지는 저장소 밖 `../runs/logs/`다. `-Destination`으로 바꿀 수 있다. `adb exec-out run-as kr.goltou.auto tar ...`의 바이너리 스트림을 그대로 받아 압축을 푼다. 소금 파일은 추출하지 않는다. 화면 캡처나 인증 데이터 전체를 가져오는 명령이 아니다.

로그는 고정 단계·사유, 수치, 허용한 요청 필드 이름으로만 구성한다. 이동 경로의 식별값은 자리표시자로 바꾼다. 글·상품·계정·밴드의 실제 이름/번호/주소와 본문·사진·인증 값은 남기지 않는다. 등록 기록과의 연결에는 기기 전용 소금으로 만든 짧은 해시를 쓴다.

등록을 명시적으로 이어하면 새 실행 로그에 retry를 남긴다. 원래 실행의 종료 줄을 고치거나 두 번째 종료 줄을 추가하지 않는다. 로그인/확인창을 기다리며 멈춘 실행도 stopped로 구분한다. 기록 재시도는 편집기 입력이나 제출을 반복하지 않는다.
