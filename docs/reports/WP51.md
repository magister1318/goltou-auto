# WP51 블로그 삭제 스크롤의 대체 좌표 검사

## 원인과 변경

- S24의 1.1.4(21)에서 수집한 trace 35에 따르면 첫 PageDown 뒤 가운데 좌표 `(640, 450)`가 `mainFrame` 안의 접근 가능한 광고 iframe과 열린 Shadow DOM을 거쳐 광고 요소에 닿았다. `body` 검사가 실패했고 WP50은 접근 불가 iframe에서만 대체 좌표를 검사해 단계 7, 두 번째 시도에서 멈췄다. 수정 기준은 `codex/v114`의 `aa43d37`이다.
- 중앙 검사에 실패하면 가로 15%·85%, 세로 30%·70%를 기존 순서대로 검사한다. 처음 통과한 지점을 기록하고 PageUp 또는 PageDown을 한 번 보낸다. 다섯 좌표가 모두 실패하면 단계 7에서 중단한다.
- `blogDeleteScroll` 로그에 지점별 판정과 실패 지점의 `inShadow` 및 `frameDepth`를 기록한다. `frameDepth`는 최상위 문서에서 진입한 프레임 문서 수다. 두 값은 각각 불리언과 0 이상의 정수로만 전송한다.
- 공통 클릭 판정의 조상 검사와 `frameBlocked` 처리, 누르기 직전 삭제 링크 확인을 유지했다. 앱 버전은 1.1.4(22)다.

## 검증

- 새 Chromium 회귀 시험을 WP50 코드에서 실행해 첫 PageDown 뒤 `BLOG_POST_DELETE_CHECK_7`로 실패하는 것을 재현했다. WP51에서는 중앙의 `inShadow: true, frameDepth: 2` 기록과 왼쪽 후보 통과, 합성 글 삭제 1회와 글 URL·목록 재확인을 검증했다. iframe이나 일반 덮개가 다섯 좌표를 모두 가리면 추가 키 입력과 클릭 없이 중단했다. 대체 좌표를 통과한 뒤 삭제 링크가 가려진 경우도 클릭 전에 중단했다.
- Node 18.20.4에서 블로그 삭제·전송 로그·CDP·밴드 회귀 시험 4개 파일의 110개 시험을 통과했다. 로그 필드의 자료형 검사와 허용 목록에 없는 광고 문자열 제거를 확인했다.
- Android `gradlew.bat :buildSrc:test testDebugUnitTest testReleaseUnitTest assembleDebug --console=plain --offline`을 통과했다. buildSrc 10개, Debug·Release 각 23개가 통과했다. 디버그 APK에서 `kr.goltou.auto`, 1.1.4(22), 내장 번들 2개와 소스 커밋을 확인했다.

- Node 18.20.4에서 `./scripts/install-device.ps1 -Variant release -VerifyOnly -ArtifactDirectory ../release-out`을 통과했다. 이 명령으로 `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test`, 서명 비밀 값 검사, 내장 런타임 소스 117개 호환성 검사, `pnpm build`, Android `assembleRelease`를 확인했다. 전체 110개 파일의 1,377개 시험이 통과했고 필수 런타임 시험 6개를 포함하며 건너뜀과 TODO는 0개였다.
- 배포 APK에서 `kr.goltou.auto`, 1.1.4(22), 내장 번들 2개, 소스 커밋, v2·v3 서명을 확인했다. APK 실측 SHA-256은 체크섬 파일과 일치했고, 서명 인증서 지문은 직전 1.1.4(21) APK 및 저장소의 공개 지문과 일치했다. `git diff --check`도 통과했다.
