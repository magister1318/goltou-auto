# WP24 실제 밴드 게시 성공 화면과 삭제 확인

시험 글은 남아 있지 않다. 앱의 `게시했습니다` 화면을 실제로 확인한 뒤 같은 글을 등록 기록에서 삭제했다. 게시 작업과 삭제 작업은 각각 단일 `succeeded`로 끝났으며, 피드·원래 주소 부재와 기록의 `삭제함`을 확인했다.

## 실행 범위

- 이번 요청문을 WP24 지시서로 적용했다. 2026-11-17 09:39 KST 소유자 승인의 한 건 게시·삭제 범위에서 실행했다.
- 기존 `codex/band-verify`와 초안 PR #25를 유지했다. 설치된 WP23 구현 커밋 `09615bfc1e6c`의 디버그 APK를 사용했다. 실행 코드 변경, 재빌드, 재설치는 없었다.
- 기기의 깨어 있음·잠금 해제·골투오토 전면 상태를 먼저 읽기만 했다. 깨우기·잠금 해제·기기 설정 변경·다른 앱 조작·네이버 조작·로그인 페이지 조작은 없었다.
- 앱의 밴드 목록/게시 WebView와 공유 밴드 프로필만 사용했다. 로그인 확인 WebView는 탐색에 사용하지 않았다. 지정된 밴드 피드에서 같은 시험 제목이 없음을 제출 전에 확인했다.
- 이전 18:14 블로그 임시저장과 같은 판매 상품을 밴드만 선택해 등록했다. 지정된 선택기 항목을 최종 확인창에서 대조했다. 본문은 이전 앱 계획과 같고 줄바꿈 158개, 사진 29장이다. 문장 다듬기·글 끝 문구·링크 카드는 모두 꺼짐이며 문구를 추가하지 않았다.
- 제출 전 첫 밴드 목록 읽기는 실패했고 다음 읽기는 성공했다. 선택기가 WebView를 다시 만든 뒤 외부 읽기 검사의 오래된 문맥을 재발견했다. 이 검사 중단은 허용 파일 생성·앱 발행 시작 전에 일어났다. 실제 게시 재시도나 실행 코드 수정은 없었다.
- 최종 확인 직전에 일회 허용 파일을 한 번 생성했다. 앱 발행 시작은 한 번, 허용 소비 한 번, 실제 생성 요청 허용 한 번이다. 생성 결정 줄과 같은 요청의 네트워크 증거 줄을 별도 제출로 세지 않았다.

## 앱 자체 로그와 실제 화면

`scripts/pull-logs.ps1`로 추출한 원래 게시 작업은 09:56:17.012에 시작해 10:02:01.693 KST에 단일 `succeeded`로 끝났다. 생성 응답이 성공했고 응답 신원을 확보했다. 주소 저장은 성공 응답 뒤 156ms이며 상세 검증 시작보다 앞선다. 피드 신원 탐색과 게시 복구 경로는 사용하지 않았다.

상세 검증 로그에서 전체 본문, 줄바꿈 158개, 사진 29장 전체 순서, 실제 해시태그 2개, 실제 링크 2개가 모두 통과했다. 앱 결과 화면 제목은 `게시했습니다`였으며 `k-result.png`에 보존했다. 등록 기록은 게시 상태이고 글 보기·삭제를 제공했다. 저장된 기록의 링크는 이번 작업의 링크와 같았다.

## 같은 글 삭제

앱의 등록 기록에서 이번 작업의 링크·상품 제목과 일치하는 행만 선택하고 밴드 삭제 확인을 눌렀다. 삭제 작업은 10:03:00.512에 시작해 10:04:51.740 KST에 단일 `succeeded`로 끝났다. 앱은 소유·대상·본문·제목·시각 신원을 검증하고 삭제 뒤 피드 부재와 원래 URL 부재를 각각 확인했다. 앱의 읽기 전용 피드 확인 화면을 보고 골투오토로 돌아왔다. 기록은 `삭제함`이고, 같은 앱 게시 WebView에서 피드를 다시 읽어 시험 제목이 없음을 확인했다.

## 확인 명령과 증거

- `pnpm install`: 성공, 잠금 파일 변경 없음.
- `pnpm -r typecheck`: 성공.
- `pnpm exec tsc -p apps/android/bridge/tsconfig.json`: 성공.
- `pnpm test`: 83개 파일·1,021개 시험 통과, 실패 0·건너뜀 0. 09:56:51 KST 시작, 758.64초, 종료 코드 0.
- `scripts/pull-logs.ps1`: 게시 전·게시 후·삭제 후 앱 자체 로그 추출 성공.
- 실행 코드와 안드로이드 파일을 변경하지 않아 `assembleDebug`와 `install -r`는 실행하지 않았다.

저장소 밖 `../runs/band-shots/`에 `k-result.png`, `k-history-posted.png`, `k-deleted.png`, `k-job-logs.png`, 식별정보 없는 `wp24-log.txt`, 30줄 이내의 `wp24-summary.txt`를 보관한다. 화면 네 장을 직접 확인했다. 실제 이름·식별값·글 주소·계정·상품 본문을 저장소에 넣지 않는다.

추가 게시나 수정 후 재게시가 필요한 상태는 없다. 이번 한 건은 성공과 삭제를 모두 확인했으며 다음 작업에 남길 실기기 글이나 미확인 삭제는 없다. 초기 목록 읽기 실패의 원인은 이번 범위에서 별도로 수정하지 않았다.
