## 구현한 것

1. `sites/band/plan.ts`의 실제 실행기가 WP4 밴드 `InputPlan`과 준비된 파일 매핑을 받는다. 기본은 모바일 UA다. 내 밴드 영역의 이름·키를 읽어 광고·추천·중복을 제외하고 확인 화면의 선택 목록에 연결한다. 계정·밴드 정보는 실제 기기에서 읽거나 저장소에 남기지 않았다.
2. 글자는 Surface의 입력·Enter 명령으로만 넣는다. 기본 문자 간격은 기존 Surface의 60ms이며 최대 32자마다 로그인·작성기·대상 밴드와 중단 요청을 확인한다. 사진은 원문 사진 순서대로 한 묶음의 파일 입력으로 첨부한다. 편집기 DOM 쓰기, setter, 합성 붙여넣기, 클립보드·사진첩 조작은 없다.
3. 작성기에서 본문과 사진 식별 파일명을 다시 읽어 `Observation`으로 바꾼다. 공백 정리한 전체 글자, 제목·문단, 가격·출발일·골프장, 사진 수·순서를 공통 비교기로 대조한다. 파일명을 읽지 못하거나 순서·글자가 다르면 게시 전 멈춤 성공으로 처리하지 않는다.
4. 사진 한도는 파일 입력의 선언값 또는 사진 개수 안내에서 관측한 값만 사용하고 관측 시각을 보관한다. 확인 화면에 관측값 또는 `미확인`을 표시한다. 관측한 한도를 넘으면 시작 버튼을 막으며, 처음 작성기를 열어 알게 된 한도도 글자·사진 입력 전에 검사한다. 재시도로 우회하지 못하고 사진을 임의로 자르지 않는다.
5. 임시저장 방식은 대조 일치 뒤 작성기 Surface를 보여 주고 `stopped_before_post`로 기록한다. 밴드에 저장된 임시글이라고 표시하지 않는다. `밴드 화면 보기`, `게시 여부 확인`, `버리기`를 연결했다. 사용자 게시 확인은 작성기 닫힘과 같은 밴드의 새 글 주소, 게시된 본문·사진 재대조가 모두 필요하다. 확인되지 않으면 게시 전 멈춤을 유지한다.
6. 사용자가 버리기를 선택한 뒤 작성 취소와 본문·사진·작성기 소멸을 확인해야 `stopped`가 된다. Android 기본 JS 확인창은 WP5와 같은 Surface 전달 방식으로 사용자 선택을 기다린다. 거절하면 작성 내용을 유지한다.
7. 목록·작성·로그인 복구는 같은 밴드 Surface를 사용한다. 앞부분과 사진이 일치하면 이어 쓰며, 내용이 바뀌면 사용자의 버리고 재시작 선택을 받아 같은 Surface에서 다시 시작한다. 로그인 풀림은 `login_paused`로 멈추고 해당 화면을 보여 주며 자격 증명을 대신 입력하지 않는다.
8. `ChannelRegistrationRunner`가 블로그 뒤 밴드를 한 곳씩 처리한다. 각 밴드의 상태와 주소는 별도 기록이다. 임시저장 방식에서는 현재 밴드의 게시 확인 또는 폐기를 끝내야 다음 밴드로 간다. 블로그 실패 뒤에는 `블로그 실패 확인 · 밴드 진행` 선택이 있어야 진행한다. 준비 실패는 건너뛰지 않는다. 모든 채널 처리가 끝난 실패 작업은 새 상품 시작을 막지 않는다.
9. `/auto/posts/start`의 `conflict`는 해당 밴드 이름과 이유를 표시하고 사이트 실행 전에 차단한다. 가짜 API에서도 게시 전 멈춤을 하루 한도에 포함하며 폐기된 작업은 제외한다. API 타입·계약에 `stopped_before_post`를 추가하고, 채널별 기록에서 밴드를 `draft_saved`로 바꾸지 않게 했다.
10. Android bridge에 밴드 실행기를 주입했다. B안의 기존 글자·가는 줄·색·실행 막대를 사용했으며 선택하지 않은 채널은 `선택 없음`으로 표시한다. 실제 밴드 자동 게시를 실행기와 게시 함수 양쪽에서 차단했다. 이번 실서비스 경로는 첫 밴드만 허용하고 실행기 수명 전체의 작성기 열기 시도를 최대 3회로 제한한다. 여러 밴드·자동 발행 경로는 루프백 가짜 페이지에서 시험했다.

## 남은 문제와 다음 작업

- 실제 밴드의 사진 파일명 보존, 업로드 후 사진 식별, 본문·사진 재관측과 기본 확인창을 새 실행기로 검증하지 못했다. 식별·대조가 안 되면 실패로 멈춘다. 소유자가 화면을 사용할 수 있고 앱 전면·화면 켜짐이 확인되는 별도 실행에서 확인해야 한다.
- 실제 사진 최대치·서버 검증은 미확인이다. `미확인`은 무제한이라는 뜻이 아니다. 최초 작성기에서만 한도를 관측할 수 있으면 입력 전에 멈추고 관측값을 알리며, 그 뒤 확인 화면에 반영한다.
- 실제 자동 게시 차단, 첫 밴드·3회 제한은 이번 작업의 안전 경계로 유지했다. 여러 실제 밴드와 실제 발행을 확인한 기능이라고 주장하지 않는다.
- API 계약·클라이언트·가짜 API만 새 상태를 반영했다. 실제 API·DB의 `stopped_before_post` 수용과 하루 한도 정책은 별도 검토·반영이 필요하다. 참고 저장소와 운영 환경은 고치거나 연결하지 않았다.
- 작성기와 관측 체크포인트는 현재 앱 프로세스 수명 안에서 유지한다. 프로세스 종료 후 복구, 이전 실행의 작성기를 기록에서 다시 찾는 것은 미검증이다. 이전 기록에는 현재 작성기와 일치하는 경우에만 화면 보기 버튼이 동작한다.
- 운영 반영과 main 푸시는 하지 않는다. 변경은 `codex/wp6-band`와 `codex/wp5-blog` 대상 초안 PR로 넘긴다.

### 남긴 글·작성 내용

밴드에 게시한 글과 남겨 둔 작성 내용은 **없다**. 밴드는 저장된 임시글로 기록하지 않았다. 네이버에 남긴 한 건의 정확한 제목은 WP5 최신 절에 있으며 이번 밴드 검증에서 삭제하지 않았다. 마지막 앱 화면은 ‘작성을 버렸습니다’이며 APK를 설치·전면 상태로 두었다.

### 고친 것과 회귀 확인

- 실제 `www.band.us` 이동을 같은 서비스로 허용했다. `band.us`/`www.band.us` 이외의 주소와 유사 도메인은 거부하는 시험을 추가했다.
- 새 홈의 `.globalMyBandWrap`와 `/my/bands` 목록을 기다리고, 전체보기와 첫 실제 밴드 타일을 입력으로 따라간 뒤 URL을 읽는다. 링크에 식별키가 없는 새 구조에서는 **첫 밴드만 반환**한다. 다른 밴드를 열어 키를 수집하지 않는다. 광고·폴더 제외와 작성기 미개방을 로컬 브라우저에서 확인했다.
- 지연 렌더링을 로그인 풀림으로 바로 처리하지 않고 준비 신호를 기다린다. 로그인 화면이 관측되면 입력하지 않는다.
- 첨부 메타데이터의 원본 파일명/URI/base64 식별을 읽을 수 있도록 보완했다. V8 읽기 전용 검사를 유지하며 DOM 쓰기나 `atob` 호출로 우회하지 않았다. 인코딩 파일명 지원과 익명 사진 5장 차단을 로컬에서 시험했다. **실제 밴드의 이번 메타데이터에는 파일명이 없어 이 보완으로 해결되지 않았다.**
- 통합 실행기의 마스킹 캡처·블로그 실패 기록 연결을 복원했다. 실제 숨김 PNG는 앱 내부 경로로 생성했다. native 밀도 캡처 대안은 좌표가 맞지 않아 제거했고 최종 compositor 캡처만 유지했다.
- 기존 로컬 모바일/데스크톱, 순서 바꿈, 로그인 풀림, native 확인창 전달, 버리기, 가짜 발행 시험을 유지했다. 실제 게시를 시험한 것은 아니다.

### 남은 실패와 다음 작업

**실제 밴드의 사진 순서를 독립적으로 식별하는 방법이 미해결이다. WP6 실기기 완료 기준을 충족하지 못했다.** DOM의 실제 첨부 타입 값만으로 사진 정체를 추정하거나, 5장이 보인다는 이유로 순서 일치로 처리하지 않았다. 원본 파일명을 보존하지 않는 업로드에 대해 화면 읽기 범위 안에서 독립적인 사진 대응을 설계·검증해야 한다. 같은 원인을 반복하는 세 번째 작성기는 열지 않았다.

새 목록의 전체 밴드 키 수집, 실제 사진 한도·서버 검증, 자연 발생 native 확인창, 프로세스 재시작 복구는 미검증이다. 운영 API·DB 변경이나 연결은 하지 않았다. 최종 코드의 네이버 입력 경로를 다시 완주한 것은 아니며 WP5의 실제 저장 성공과 이후 자동복구 보존 중단을 구분한다.

`pnpm install`, `pnpm typecheck`, `pnpm test`(**17개 파일·129개, 건너뜀 0개**, 최종 80.70초), `pnpm build`, `./gradlew.bat assembleDebug --console=plain --no-daemon --offline`(**14초**) 통과. 최종 APK는 **64,103,014바이트**, SHA-256 `c0f6d28e7093b12c3acf284c9052fa05376fed50eb8f19508db12369d76879c2`다. 최종 설치 engine과 dist 일치 및 화면 켜짐·앱 전면도 확인했다. APK·캐시·local.properties·임시 실행기는 커밋하지 않는다. 변경은 기존 `codex/wp6-band`와 초안 PR #6에 반영하며 main/운영 반영은 하지 않는다.
