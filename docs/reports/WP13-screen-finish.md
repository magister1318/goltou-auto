B안의 글 중심 목록·초록·가는 줄을 지켰다. 긴 제목 줄바꿈, 여백, 오류·빈 목록·불러오기·재시도,
진행·기록 화면과 44px 누름 영역도 확인했다. 일반 화면에서 진단 문구가 나오지 않도록 했다.
실기기에서 흰 상태 표시줄의 글자가 흐려 보여 어두운 글자로 바로잡았다.
사진 주소 제한은 기존 함수를 브라우저에서도 함께 쓴다. Android 요청 차단과 CSP도 골투 사진에만 열었다.

확인 결과:

- `pnpm install`, `pnpm -r typecheck`, bridge를 포함한 `pnpm typecheck`, `pnpm build`: 통과.
- 루트 `pnpm test --reporter=verbose --maxWorkers=1 --no-file-parallelism`: **35개 파일, 338개 시험 통과**. 새 사진·서비스 화면 시험 19개 포함. 초기 병렬 실행은 완료 전 중단했고 최종 전체 실행은 499.26초에 끝났다.
- `apps/android`에서 `./gradlew.bat assembleDebug testDebugUnitTest --console=plain`: 통과. Android 주소 정책 시험 **2개**, 실패 0.
- APK 자원의 adaptive·round·단색 레이어 연결을 확인했다. 48px 자원 모양도 따로 렌더해 확인했다.
- 실기기: **6장**. `01-home.png`, `02-list.png`, `03-preview.png`, `04-settings.png`, `05-naver.png`, `06-band.png`. 목록 썸네일 8개와 미리보기 사진의 실제 수신·표시를 확인했다.
- 오프라인 시뮬레이터: **17장**. 같은 주요 6장에 `sim-`을 붙였고, 추가로 골투 로그인, 밴드 미리보기, 기록, 빈 목록·오류, 진행, 재로그인, 사진 실패, 아이콘 자원 보기를 남겼다.
- 사진 80장 미리보기에서 맨 끝으로 이동해도 요청은 **3~5장**이었다. 390×844 화면의 44px 누름 영역, 200% 글자 크기에서 가로 넘침 없음, 로그인 안내의 열기·확인·돌아가기를 검사했다.

PNG는 모두 저장소 밖 `../runs/wp13-shots/`에 있다. 재현 명령은
`pnpm build` 뒤 `node scripts/screen-finish.mjs --photos ../refs/goltou-hybrid/MOBILE/static/image`다.
시뮬레이터는 참고 저장소의 로컬 예시 사진으로만 응답을 대체했다. 기본 `pnpm sim:finish`는 내장 도형 예시를 쓴다.
실제 원문·계정 자료와 PNG는 커밋하지 않았다. 서버·DB에 직접 접속하거나 수정하지 않았다.
화면 시뮬레이터는 작업 시작 명령을 거절하며 진행·재로그인은 고정 상태만 보여 준다.

처음에는 기기가 `Dozing`이라 건드리지 않았다. 뒤에 읽기만 해서 확인했을 때 `Awake`이고
앞 화면이 `kr.goltou.auto.MainActivity`여서 `adb install -r`로 갱신했다. 골투 로그인은 유지됐다.
각 입력 전 앞 앱과 누를 요소를 확인했고 앱 안에서 상품 조회·미리보기·설정·로그인 안내만 열었다.
등록 시작·임시저장·발행·네이버/밴드 페이지 입력·깨우기·잠금 해제는 하지 않았다. 끝에는 홈으로 돌아왔다.
앱 밖을 조작하지 않기 위해 런처 캡처는 생략했다. 남은 확인은 실제 런처의 마스크·테마 적용 모양이다.
