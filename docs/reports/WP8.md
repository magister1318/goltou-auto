## 로컬 확인과 APK

외부 요청을 막은 로컬 Chromium의 긴 편집기로 사진 36장 각각 1파일 전달, 모든 완료 수 갱신, 새 편집기에서 보이는 사진만 식별자가 나타나는 지연 로딩과 중첩 스크롤을 재현했다. 저장 1회·재열람 일치·발행 0회를 확인했다. 숫자 취소선 시험은 세 태그·중첩·문자만 있는 태그·제외 요소·본문 미저장을 검사한다. 추정 시험은 3장 이전 숨김, 실제 관측 평균 반영, 남은 글자 시간, 완료/채널 변경 초기화를 검사한다. 밴드는 기존 한 장씩 업로드에 시간 측정이 붙었음을 로컬에서 확인하며 실제 한도 관측을 대신하지 않는다.

| 확인 명령 | 최종 결과 |
| --- | --- |
| `pnpm install` | 통과, 잠금 파일 변경 없음 |
| `pnpm typecheck` | 통과, 공통 패키지·UI·Android bridge |
| `pnpm test` | **22개 파일·174개 통과, 건너뜀 0개, 291.61초** |
| `pnpm build` | 통과, Node 18 대상 엔진·UI·Android 자산 |
| Android `./gradlew.bat assembleDebug --console=plain --no-daemon --offline` | 통과, 저장소 `.gradle-cache`, 최종 14초 |
| `git diff --check` | 통과 |

실기기 설치본 APK는 **64,103,014바이트**, SHA-256 `f4b16181c55826d601fe9fa1c4048806d064bee9745b8d093b976289672939c4`이며 설치 엔진과 해당 dist의 바이트 일치를 확인했다. 이 설치본으로 블로그 완료와 60개 점검을 수행했다. 이후 기존 밴드 한 장씩 첨부 경로에도 같은 시간 지표를 연결했다. 최종 APK는 같은 바이트 수, SHA-256 `4c2b13309ba7408fa1943986c091b06746027f5f8becc1609d3d53c0520f0d86`이며 APK 내장 engine·manifest와 최종 dist가 일치한다. [최종 APK 수치](wp8/apk.json)를 남겼다. 전면 조건 상실 후에는 최종 APK를 재설치하거나 기기를 추가 조작하지 않았다. 따라서 그 밴드 시간 지표의 실기기 확인은 미실행이다.

## 다음 작업·정리

- 밴드 실제 사진/글자 한도, 입력 전 초과 차단, 게시 전 멈춤·버리기·잔여 없음 확인을 다음 기기 작업에 넘긴다. 이번 생략을 성공으로 기록하지 않는다. 새 기기 작업에서도 전면·화면 켜짐과 로그인 확인이 필요하다.
- 한도를 확인한 뒤 WP7 60개 기준 초과 수를 확정하고 사진 처리 정책은 사용자에게 결정받는다. 현재 잘라내기·사진 선택·여러 글 나누기 기능은 없다.
- 새 네이버 임시글 1건은 15:18:53 KST 저장본으로 남긴다. 삭제하지 않았다. 실제 밴드 새 작성 내용은 없다.
- 이번 PID 한정 PC 중계 `tcp:19221`은 제거했다. 기존 `tcp:19220`은 건드리지 않았다. 임시 관찰 도구·원시 자료·APK·생성 자산·캐시·local.properties는 커밋하지 않는다. 저장소에는 상품 번호와 수치·판정만 남긴다.
- 운영 API는 앱의 정상 읽기와 등록 기록 경로만 사용했고 운영 DB 직접 연결·운영 변경은 없다. main 직접 푸시·병합·배포는 하지 않는다. 브랜치를 커밋·푸시하고 main 대상 초안 PR로 넘긴다.
