# WP46 블로그·밴드 작업 추적 로그

## 구현

- Android 버전을 1.1.3(versionCode 17)으로 올렸다. 블로그 임시저장·발행·삭제와 밴드 게시·삭제에 작업별 `jobId`를 부여한다. 같은 글의 게시·삭제도 각각 보낸다. 발행 주소를 확인했지만 상세 판독이 남은 실행은 `incomplete`로 기록한다.
- 앱은 `/auto/posts/trace`로 성공·실패·멈춤 등의 final을 보낸다. 3분 경과 후 사진 입력 완료, 제출 직전, 판독 완료에 partial을 보낸다. HTTP 404·405에서는 `/auto/posts/log`를 사용한다. 나머지 전송 오류와 앱 종료는 사용자별 재전송 큐가 처리한다. 큐는 7일간 최대 20건을 유지하며 기기의 `runner.log_upload`에 결과를 남긴다.
- 요약에 마지막 단계, 검사별 기대·관측 값과 결과, 사용한 사진 출처 및 시도, 단계별 소요 시간 상위 10개를 넣었다. 상세 줄에 시작 기준 시각 `t`와 결정 줄을 넣었다. 비교와 실패를 우선 보존하면서 UTF-8 512KiB를 지키고, 줄이 줄어든 수를 `droppedLines`에 기록한다.
- API 클라이언트에 새 계약과 가짜 구현을 추가했다. [작업 추적 로그](../logging.md)에 운영 진단 순서와 허용 목록 관리 방법을 기록했다.

## 기존 전송본에서 빠지던 항목

| 확인한 항목 | 기준 커밋 `add7e31`에서의 상태 | WP46 |
| --- | --- | --- |
| `dialog`, `connection`, `bandList`, `update` | 기기 로그에 기록해도 `uploadTail`의 필드 재구성에서 누락 | 공통 투영에서 보존. 서버 연결 경로는 고정 호스트와 경로 모양으로 한 번 더 제한 |
| `band.photo.detail_api`, `band.photo.cached_feed`, `band.photo.recovery_feed`, `band.photo.detail_dom` | 네 단계와 고정 `reason`은 기준 커밋에 등록되어 있었음. 성공 시 서버 전송이 없었고, 사진 출처를 채택한 결과를 나타내는 필드는 없었음 | 성공·실패 전송본 양쪽에서 출처 진단을 확인. `band.photo.selected`와 `photoSource`로 채택한 출처를 기록 |
| 경과 시각, 결정 줄, 검사표 | 기존 전송본에 없음 | `t`, `decision`, `summary`에 기록 |
| 판독 실패의 비교값 | 블로그 제목·사진·숫자 및 일부 서식 실패에서 한쪽이나 양쪽 수치가 생략됨 | 실패 호출에서 두 비교값을 타입으로 요구. 결정 줄에도 같은 비교값 기록 |

기준 커밋의 소스에서 WP45의 네 단계가 전송 허용 목록에 있었음을 확인했다. 1.1.2 이전 실기기 전송본에서 빠진 직접 원인은 로컬 재현으로 확인하지 못했다.

## 검증

- `pnpm install --frozen-lockfile` 통과.
- `pnpm typecheck`, `pnpm build`, `pnpm check:secrets` 통과.
- `pnpm test --maxWorkers=4`에서 110개 파일, 1,358개 시험이 모두 통과했다. JSON 결과에서 필수 런타임 시험 6개, 건너뜀 0개, TODO 0개를 확인했다.
- Node 18.20.4에서 추적·API·런타임 및 밴드 삭제 복구 관련 시험 92개 통과. 실행 소스 114개와 코어 번들 2개의 호환 검사 통과.
- Android에서 `gradlew.bat assembleDebug --console=plain --no-daemon --offline` 통과. APK에서 패키지 `kr.goltou.auto`, 버전 1.1.3, versionCode 17을 확인했다.
- 전체 실행에서 발견한 두 회귀를 수정했다. 밴드 삭제 복구는 게시 요청·응답 성공 줄을 증빙으로 집계한다. 66장 전송본은 반복 응답과 같은 값을 가진 결정·성공 검사 줄을 묶는다.
- 합성 브라우저에서 블로그 임시저장·발행·삭제, 밴드 게시·삭제의 요약 검사표를 확인했다. 66장 사례에서 API·DOM 출처, 부분 판독, 경과 시각, 결정 줄을 확인했다.
- 브라우저 시험은 합성 편집기·상세 페이지를 사용한다. 운영 서버·DB 접속, 실제 게시, 휴대폰 설치는 수행하지 않았다.

## PASS03에서 확인할 사항

- 서버 구현은 PASS03 범위다. 앱은 새 계약에 맞춰 전송하며, 가짜 서버와 합성 응답으로 검증했다.
- `/auto/posts/start`가 유효한 `postNo`를 반환하기 전에 실패하면 해당 작업을 서버와 연결할 번호가 없다. 이 경우 `record / POST_RECORD_START_FAILED`를 기기에 기록한다.
- 재전송 본문은 기기의 JSONL에서 읽는다. 로그 저장소 전체 50MB 보존 한도와 기존 기기 모델 허용 목록을 적용한다.
- 설계 링크는 이 환경에서 열리지 않아 실행 폴더의 한글 WP46 지시서에 옮겨진 계약을 기준으로 구현했다.
