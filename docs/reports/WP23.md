# WP23 결과 화면 안전과 저장 후 대조 허용 범위

초안 PR #25의 기존 `codex/band-verify`에서 작업했다. 이번 요청문을 WP23 지시로 적용했다. 실제 밴드·네이버 접속, 로그인, 읽기, 저장, 발행, 삭제를 실행하지 않았다. 실기기 게시 허용 파일을 만들거나 소비하지 않았다. 휴대폰 작업은 마지막 APK 덮어쓰기 설치 한 번뿐이다. 앱 실행이나 화면 조작은 하지 않았다.

## 결과 화면과 중복 방지

- 저장·게시 전 실패, 임시저장 확인, 게시 확인, 생성 결과 불확실을 구분하는 생성 증거를 보관한다. 입력 직전에 불확실로 전환하며 성공 주소나 저장 응답·임시글 신원을 얻으면 구체화한다.
- 생성된 글의 검증 실패는 `게시는 됐지만 확인할 점이 있습니다`, `발행은 됐지만 확인할 점이 있습니다`, `임시저장은 됐지만 확인할 점이 있습니다`로 표시한다. 결과가 불확실하면 저장·게시 여부를 확인하라는 제목을 쓴다.
- 해당 결과의 주 행동은 `등록 기록에서 보기`, 보조 행동은 `닫기`다. `다시 시도`와 `이어하기`는 제공하지 않는다. 화면 닫기와 기록 이동은 서비스 입력을 실행하지 않는다. 기록 저장 실패에는 글을 다시 만들지 않는 별도 `기록 다시 시도`만 본문에 남긴다.
- 생성 없음이 확인된 실패만 재시도한다. 과거 기록에서 생성 증거가 없다는 이유만으로 재시도를 허용하지 않는다. 이미 소진된 밴드 게시 승인도 재사용하지 않는다. 실행기의 재개 경로에서도 저장 후 실패 재실행을 거부한다.
- 오류에 본문·주소를 넣지 않고 비교 항목과 순번만 보관한다. 예: `링크 주소 2번째가 계획과 다릅니다.` 사진 수·순서, 본문, 줄바꿈, 문단 굵기도 구분한다.
- 블로그 검증 실패도 확인된 발행 주소를 등록 기록에 보존한다. 주소가 있는 게시 후 실패 행에서 글 보기와 기존 신원 확인을 거치는 삭제를 제공한다. 기존 소유·대상·제목 확인과 삭제 확인창은 유지한다.

## 밴드: 계획과 게시된 글의 비교 전 항목

| 항목 | 비교와 허용 결정 |
| --- | --- |
| 전체 본문·제목·가격·출발일·골프장 | 계획 전체 문자열과 상세 본문을 대조한다. 제목과 수치도 이 문자열 안에 포함된다. 기존 CRLF 통일, U+200B~U+200D·BOM 제거, 각 줄 끝 공백과 문서 끝 공백 제거만 유지한다. 본문 단어·기호·내부 공백을 추가로 정리하지 않는다. |
| 줄바꿈 수 | 위 계획 문자열의 개행 수와 상세 읽기 값이 같아야 한다. 중간 빈 줄 접힘을 새로 허용하지 않는다. 피드의 접힌 미리보기를 전체 본문 증거로 쓰지 않는다. |
| 사진 수·순서 | 업로드 증거 전체와 상세 사진 전체를 같은 순서로 대조한다. 기존 경로 신원 비교를 유지하며 호스트·쿼리의 썸네일 변환만 경로 밖 정보로 취급한다. 빈 경로는 통과하지 않는다. 작성기의 사진 순서·크기 증거도 그대로다. |
| 자동 해시태그 | 상세 DOM의 실제 태그 문구와 위치를 읽는다. 각 태그가 계획의 같은 위치에 있는지, 실제 개수와 배열·순서가 일관적인지 확인한다. 다른 서비스의 정규식으로 밴드 예상 태그 수를 추측하지 않는다. 태그 탐색 주소는 일반 외부 링크에서 제외한다. |
| 자동 링크 | 상세 DOM의 표시 문구·목적지·본문 내 위치·순서를 읽는다. 해당 위치의 계획 URL 접두 부분을 URL 직렬화했을 때 실제 목적지가 되는지 대조한다. 목적지가 다른 위치에 등장한다는 이유로 통과시키지 않는다. 예상 정규식의 링크 개수·끝 경계와 같아야 한다는 조건을 없앴다. |
| 글 신원 | 생성 응답 또는 유일한 최근 소유 글의 대상·주소 신원, 상세 페이지의 동일 주소를 확인하는 기존 경로는 유지한다. 주소 확보와 내용 일치의 의미는 구분한다. |

본문이 같으면 서비스가 URL의 닫는 괄호·대괄호·문장부호·한글 조사 중 어디에서 자동 링크를 끝내는지 그대로 따른다. 관측 목적지가 계획의 같은 위치에 포함되지 않으면 링크 순번을 가진 확인 필요 결과다. 실제 본문·사진·줄바꿈 불일치는 계속 확인 필요로 남으며 성공으로 바꾸지 않는다.

## 블로그: 계획과 저장·발행 후 읽기의 비교 전 항목

| 항목 | 비교와 허용 결정 |
| --- | --- |
| 제목 | 기존 공백·제로폭 정리 비교와 제목 신원 확인을 유지한다. 제목 읽기의 바깥 공백 제거도 기존 동작이다. |
| 전체 본문·글자 수 | 공통 대조는 공백·U+200B~U+200D·BOM을 제외한 문자열과 글자 수를 비교한다. 이어지는 문단 서식 대조가 각 비어 있지 않은 문단의 정확한 문자열과 읽은 런 문자열을 다시 비교한다. 새 본문 정규화는 추가하지 않는다. |
| 문단 내용·수·순서, 글과 사진의 배치 | 계획의 비어 있지 않은 줄과 실제 토큰 전체를 순서대로 대조한다. 기존 읽기에서 제외하는 빈 문단만 기존대로 허용한다. 문단 합치기·순서 바꾸기를 추가로 허용하지 않는다. 표는 기존 행과 셀 글자 순서로 비교한다. |
| 사진 수·순서·신원 | 파일의 원본 해시와 순번을 담은 이름을 실제 사진 토큰과 대조한다. 서비스의 파일 확장자 변환만 허용하는 기존 기준이다. 사진 누락·교체·순서 변경은 거부한다. |
| 가격·출발일·골프장 | 각 배열의 수·값·순서를 공통 대조로 확인한다. 원본 API 사실과 계획을 대조하는 선행 검증도 유지한다. 숫자 대체나 관대한 수치 비교는 추가하지 않는다. |
| 문단 굵기 | 인접한 동일 서식 런만 합친 뒤 글자별 굵기 구간을 정확히 비교한다. 서식 없는 읽기 증거를 성공으로 취급하지 않는다. |
| 명시 링크 | 계획에 목적지가 명시된 글자 구간과 실제 href를 정확히 비교한다. 명시 링크의 대상이나 범위를 자동 링크 허용 규칙으로 덮지 않는다. |
| 추가 자동 링크 | 계획에서 링크가 없던 URL 글자에 서비스가 자동으로 만든 앵커만 허용한다. 정확히 같은 문단 위치에서 실제 목적지가 계획 URL의 접두 부분과 일치해야 한다. 본문과 굵기의 정확한 비교는 별도 유지한다. |
| 태그 메타데이터 | 저장 전에는 기존 관측 기반 편집기 태그 규칙으로 입력을 확인한다. 저장 후에는 명시 태그가 모두 정확히 남아 있어야 하고 중복은 거부한다. 자동 태그는 계획 본문의 # 뒤에 실제 문구가 포함되는지 확인한다. 서비스 메타데이터의 순서는 무관하며 자동 태그 개수·문장부호 경계를 정규식으로 다시 추측하지 않는다. |
| 임시글·발행 신원과 공개 범위 | 저장 전후 임시글 목록 변화·응답 신원, 유일한 제목, 발행 응답/결과 주소, 선택된 공개 범위와 비공개 표시 확인을 유지한다. 저장 완료와 내용 확인 완료는 별개다. |

## 문자 형태별 검토

| 형태 | 결정 |
| --- | --- |
| URL 뒤 `) ] . , ! ? " '` 및 붙은 한글 조사 | 자동 링크 목적지만 실제 서비스 경계를 따른다. 해당 문자와 한글은 본문에 그대로 남아야 한다. 균형 괄호·인코딩된 주소도 포함한다. |
| 공백·줄 끝·빈 줄 접힘 | 밴드는 기존 줄 끝 정리 외의 내부 변경을 허용하지 않는다. 블로그는 기존 빈 문단 생략과 정확한 비어 있지 않은 문단 대조를 유지한다. |
| 이모지 변형 선택자·피부색·결합 이모지 | 새로운 동등 취급을 추가하지 않는다. 블로그 정확한 런 비교는 변형을 구분한다. 밴드의 기존 U+200D 제거는 남아 있으나 이 범위를 넓히지 않는다. |
| 해시태그 뒤 문장부호·경계 | 자동 태그는 실제 서비스의 결과를 기준으로 계획 위치/문구 포함 여부를 확인한다. 본문 글자는 바꾸지 않는다. 명시 블로그 메타데이터는 그대로 보존한다. |
| 전각·반각 | 서로 바꾸지 않는다. 본문 차이로 검출한다. |
| 제로폭 문자 | 기존 제거 범위만 유지한다. 블로그의 정확한 문단 런 대조에서는 차이가 계속 검출된다. |
| NFC/NFD | 새 정규화를 추가하지 않는다. 정확한 문자열 기준을 유지한다. 이번 범위에서 실제 서비스 변환 여부를 조사하지 않았다. |

## 확인과 인계

로컬 고정 페이지와 합성 자료만 사용한다. 종료 상태별 버튼, 알려진 게시/임시저장/불확실 결과, 두 실행기의 저장 후 본문 불일치와 재실행 거부, 두 서비스의 주소 기록, 괄호·문장부호·한글 조사·줄 끝 URL, 태그 문장부호, 같은 계획의 다른 위치 목적지, 사진 수·순서 변경, 기존 문자 정규화 기준을 시험한다. 실제 페이지 읽기 시험은 부작용 금지 CDP 읽기와 외부 요청 차단을 사용한다.

첫 전체 시험은 코드·시험 추가가 끝나기 전에 시작해 이전 읽기 코드와 새 시험이 섞였고, 태그 탐색 앵커를 일반 링크로 세는 1개 실패가 있었다. 수정된 파일의 집중 회귀시험 100개와 별도 종료·삭제 정책 시험 67개는 모두 통과했다. 마지막으로 태그 버튼 문구 양끝 공백을 기존 태그 읽기와 같은 기준으로 정리했고, 본문 자체는 계속 정확히 대조한다. 이 보정 뒤 집중 시험 4개 파일·63개가 통과했다. 진행 중이던 두 번째 전체 실행은 중단하고 완료 수치로 세지 않았으며, 최종 소스를 고정한 뒤 전체 시험을 새로 시작했다. 최종 결과는 아래에 기록한다.

- `pnpm install`: 성공, 잠금 파일 변경 없음.
- `pnpm -r typecheck`: 성공.
- `pnpm exec tsc -p apps/android/bridge/tsconfig.json`: 성공.
- 최종 `pnpm test`: 83개 파일·1,021개 시험 통과, 실패 0·건너뜀 0. 09:25:29 KST 시작, 754.75초. 최종 소스를 고정한 새 프로세스의 결과다.
- `apps/android/gradlew.bat assembleDebug --console=plain`: 성공. 구현 커밋에서 APK를 다시 빌드했다.
- `adb install -r`: 1회 실행, `Success`. 휴대폰에 다른 명령을 실행하지 않았다.

기존 실패 작업을 성공으로 바꾸거나 재게시하지 않았다. 과거 실패에 항목·순번 증거가 없으면 이를 새로 추정하지 않으며 일반 확인 안내를 유지한다. 블로그 임시저장은 기존 네이버 임시저장함 안내를 사용한다. 임시글 자체의 주소와 안전한 삭제 신원은 기존 기능에서 제공하지 않으므로 새 임시글 삭제 경로를 만들지 않았다. 실제 서비스에서 새 검증 기준이 어떻게 읽히는지는 이번 작업에서 확인하지 않았다. 다음 실제 시험은 별도 승인 범위다.
