## 한 일

### API 클라이언트

- `packages/api-client`에 계약의 9개 POST 경로에 대한 입력·응답 타입과 `ApiClient`를 만들었다.
- HTTP 구현은 서버 주소와 fetch를 주입받고, 호출자가 요청마다 토큰을 넘긴다. 로그인에는 Authorization을 붙이지 않는다. 봉투·HTTP·네트워크·JSON 오류를 `code`가 있는 `ApiError` 하나로 전달한다. 실제 HTTP 구현은 이번 앱에 연결하지 않았다.
- 같은 인터페이스의 가짜 구현에 상품 16개, 상품 상세·검색·출발 월·페이지·미등록 필터, 채널별 기록, 설정과 세션을 넣었다. manager/staff/admin 권한, 일반 회원(0~2) 차단, 타인 기록 수정 금지, 밴드 하루 한도, 저장 완료 기록을 running으로 되돌리지 못하는 규칙도 재현한다.
- 예시 계정은 `manager`, `staff`, `admin`, `member`, 비밀번호는 `demo`다. 실제 계정이 아니며 가짜 주소는 `example.invalid`만 사용한다.

### 코어와 실행기 경계

- `packages/core/src/protocol.ts`에 로그인/로그아웃, 상품·기록·설정, 서비스 상태(확인됨/풀림/모름), 로그인 자리 표시/숨기기/지우기, 작업 시작/멈춤/이어하기와 진행 알림 타입을 정의했다.
- UI는 기존 로컬 `/ui-socket`을 통해 `AppCore`에 요청하고 스냅샷을 받는다. 골투 토큰은 UI 응답·브라우저 저장소에 넣지 않고 코어의 `MemoryTokenStore`에서만 관리한다. 비밀번호는 로그인 후 입력 상태에서 지우고 저장하지 않는다.
- `RegistrationRunner` 인터페이스와 교체용 factory를 뒀다. 현재 구현은 타이머로만 동작하는 `FakeRegistrationRunner`다. 실제 Surface를 만들거나 사이트를 열지 않는다.
- 한 번에 한 작업만 시작하며, 진행·사용자 중단·로그인 풀림·실패 상태에서는 다른 작업과 로그아웃을 막는다. 멈춘 단계·단계 안 진행 수·기록 번호를 유지한 채 이어 하고, 먼저 저장한 채널은 재실행하거나 running으로 되돌리지 않는다.
- 발행은 해당 작업에서 선택하고 UI의 추가 확인을 거친 뒤 `publishConfirmed: true`로 요청해야 한다. 새 상품 선택의 기본은 항상 임시저장이다. 실제 공개 없이 가짜 결과만 기록한다.

### 화면

- 골투 로그인·일반 회원 안내, 홈의 서비스 상태·검색·전체/안 올린 상품/출발 월·더 보기·아래 탭을 구현했다.
- 확인 화면의 블로그/밴드 전환, 예시 본문·가격·날짜·골프장·사진 자리·상품 주소, 원문 대조 줄, 임시저장/발행, 채널 스위치와 밴드 선택, 기본 꺼짐인 선택 옵션을 연결했다.
- 진행 화면, 사용자 멈춤/이어하기, 로그인 풀림과 보관 단계·로그인 자리·나중에 하기, 실패와 다시 시도를 연결했다.
- 기록의 본인/전체 권한, 채널별 결과·실패 이유·대상 이름, 확인하고 발행·주소 복사·다시 시도, 상품 변경 표시를 구현했다. 전체 기록은 직원·관리자에게만 보인다.
- 설정에는 계정·로그아웃, 가짜 서비스 로그인 지우기, 관리자 전용 공통 설정 저장, 가짜 실행의 로그인 풀림·실패 설정과 WP1 진단을 뒀다.
- React 상태와 작은 연결 저장소 하나만 사용한다. History API로 화면을 이동하고 Android `MainActivity.kt`의 뒤로 처리 한 줄만 수정했다. 보이는 Surface가 없으면 WebView의 이전 화면으로 돌아간 뒤 루트에서 앱을 닫는다. 다른 Kotlin 코드는 바꾸지 않았다.

## 시뮬레이션과 확인 결과

`pnpm sim`은 설치된 Chromium의 새 프로필에서 390×844 앱을 열고 Ctrl+C까지 유지한다. `pnpm sim:check`와 `pnpm sim:shots`는 같은 실행 경로를 headless로 검사한다. 시뮬레이터는 127.0.0.1 요청만 허용하며, UI와 진단용 숨김 브라우저 모두 외부 요청을 차단한다. 실제 서비스 페이지 요청은 0건이었다.

| --- | --- |
| `pnpm install` | 성공. 새 외부 라이브러리 추가 없이 workspace 의존성 연결 |
| `pnpm typecheck` | 성공. 모든 공통 패키지와 Android bridge 포함 |

| WP1 진단 | 설정 → core → 실제 CDP → 로컬 예제 제목 읽기 성공 |

API 시험은 모든 경로의 토큰 헤더, 로그인 헤더 제외, 성공 봉투, 여섯 오류 코드, 잘못된 봉투·연결·JSON·HTTP 오류, 등급·조회·설정·기록·한도를 확인한다. 실행기 시험은 한 작업 제한, 멈춤·이어하기·실패·발행 결과, 로그인 풀림 때 사진 3/5 보존, 블로그 저장 뒤 밴드 로그인 풀림에서 기록 번호를 유지하는 것을 확인한다.

UI 시뮬레이션은 로그인 → 상품 선택 → 임시저장 실행 → 완료 → 기록을 실제 버튼으로 통과한다. 발행 추가 확인 전에는 작업이 없다는 점, 관리자 설정 저장, 매니저의 전체 탭 숨김, 직원의 전체 기록, 일반 회원 차단, 로그인 풀림 후 같은 작업 이어하기, 서비스 상태 확인과 로컬 진단을 확인한다.

초기 캡처 실행에서는 같은 가짜 데이터에 등록을 반복해 밴드 하루 한도에 걸렸다. 장면마다 새 코어·가짜 API를 만들도록 고쳤고, 한도 자체는 단위 시험으로 확인했다. 뒤로 가기 보완 중 서비스 표시 요청과 숨김 요청이 경쟁하는 문제도 시뮬레이션에서 발견해, 숨김을 실제 뒤로 이동 시점에만 보내도록 수정했다. 최종 검증은 수정 후 다시 통과했다.

## 시안과 다른 곳 및 이유

- B안 색 토큰, Noto Sans KR 400/500/700/900, 제목·상품 제목 크기, 24px 좌우 여백, 가는 구분선, 사진 자리, 스위치와 아래 실행 막대를 따른다. 카드·그림자·테두리 상자·왼쪽 색 띠·이모지는 추가하지 않았다.
- 홈 상태 줄은 시안의 골투/블로그/밴드 대신 WP3 메시지 약속의 네이버/밴드/AI를 세 개의 직접 누르는 항목으로 표시하고 확인됨/풀림/모름을 모두 글자로 쓴다. 골투 계정은 머리 부분과 설정에 있다. 각 항목의 44px 영역 때문에 상태 줄과 뒤 목록의 시작 위치에 몇 px 차이가 있다.
- 예시 상품은 42개 대신 16개이며 기록 수와 날짜·등록 표시는 가짜 API의 실제 상태를 따른다. 출발 월은 실제 선택 가능한 탭과 월 입력으로 만들었다. 밴드의 대상 고르기를 누를 수 있게 추가했다.
- 확인 화면의 '전체 보기'도 44px 높이를 확보하므로 원문 대조 줄과 아래 설정이 시안보다 약 20px 아래로 간다. 추가 옵션·전체 내용·발행 확인은 아래로 스크롤해 볼 수 있다.
- 진행 단계 옆에는 완료/진행 중/대기/멈춤을 명시하고 진행 막대는 실제 가짜 작업 상태로 계산한다. 고정된 시안의 보조 문구·55%와 차이가 있다.
- 로그인 풀림 영역은 실제 네이버 도메인·화면처럼 오해하지 않도록 가짜 로그인 화면이라는 문구를 썼다. 실제 페이지를 열지 않았다.
- 기록에는 대상 이름과 API 기록별 결과를 보여 준다. 같은 상품에 여러 번 등록한 기록도 숨기지 않아 행 높이·문구가 시안과 다를 수 있다. 매니저에게는 전체 탭을 아예 표시하지 않는다.
- 시안에 없는 로그인·설정·권한 안내는 같은 토큰과 목록 구분선을 썼다. 큰 글자는 상대 크기와 줄바꿈을 허용하고, 화면 하단 막대는 스크롤 중에도 접근할 수 있게 유지했다.

## 확인하지 않은 것 / 다음 작업에 넘길 것

- **실기기 미확인**. Android 뒤로 버튼, 실제 WebView 글자 확대·키보드·접근성, Activity 재생성은 빌드만으로 확인할 수 없다. 에뮬레이터나 기기에 설치하지 않았다.
- 실제 골투 API·운영 서버·DB, 네이버·밴드·구글 페이지, 실제 로그인·발행, 배포는 수행하지 않았다. GitHub의 요청된 브랜치 푸시·초안 PR 외 운영 반영은 없다.
- 토큰 영구 보관은 구현하지 않았다. `TokenStore`를 껍데기의 보안 저장소 채널과 연결해야 한다. 현재 코어 종료 시 토큰·가짜 기록·설정은 사라진다.
- 서비스 로그인 보이기·숨기기·확인·지우기는 현재 가짜 상태 조작이다. 실제 서비스의 Surface 표시·상태 판독·프로필 삭제와 연결하는 작업은 후속 WP에서 해야 한다.
- 본문 변환·AI·사진 내려받기·실제 편집기 입력·저장 후 다시 읽기는 구현하지 않았다. 미리보기는 API 예시 값이며 '원문과 일치'는 예시 데이터의 숫자·장수 표시다. 실제 원문 대조와 저장 확인은 WP4~6이 맡는다. 선택 옵션도 실행 요청에 전달하며 실제 문장을 바꾸지 않는다.
- 기록의 '확인하고 발행'은 예시 상품을 발행 선택 상태로 다시 확인하고 추가 확인을 받는 가짜 흐름이다. 실제 임시저장 글 열기·재사용은 후속 등록 엔진에서 연결해야 한다.
- PC 검사는 Node 24.19.0과 기존 Chrome 157.0.8103.50에서 실행했다. Node 18 대상으로 번들하고 Node 18 타입으로 검사했지만 내장 Node 18.20.4 실행은 실기기에서 확인하지 않았다.

GitHub 명령에는 `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`를 설정했고 기존 gh 인증을 사용했다. 병합 때 작성자 정보가 없어 `gh api user`의 공개 이름·noreply 이메일을 이 저장소의 로컬 Git 설정에만 지정했다. 계정 선택·로그인 창은 나타나지 않았다. APK·생성 번들·캐시·`local.properties`·서명 키는 커밋하지 않는다.
