# WP50 블로그 삭제 스크롤의 광고 iframe 대응

## 원인과 변경

- S24의 1.1.4(20)에서 첫 PageDown 뒤 1280×900 화면 중앙이 다른 출처의 광고 iframe 위에 놓였다. 삭제 준비 단계의 item 7이 `body` hit 검사를 통과하지 못해 다음 PageDown 전에 멈췄다. 수정 기준은 `codex/v114`의 `0608099`다.
- 화면 중앙에서 접근할 수 없는 iframe이 확인되면 같은 높이의 가로 15%·85%, 중앙 가로의 세로 30%·70%를 순서대로 확인한다. 처음 통과한 좌표를 기록한 뒤 기존 PageUp 또는 PageDown을 한 번 보낸다. 중앙의 다른 실패 또는 후보 전체 실패는 item 7에서 중단한다. 좌표 검사는 화면을 읽으며 클릭이나 포커스 이동을 하지 않는다.
- `blogDeleteScroll` 결정 로그에 좌표, 실행·반복 번호, 판정(`retry`, `ok`, `fail`)을 기록한다. 실패한 hit는 허용 목록의 태그와 클래스, iframe 여부를 포함한다. 본문, iframe ID·URL, 임의 클래스·레이블은 전송 로그에서 제외한다.
- 안정 좌표의 삭제 링크를 누르기 직전에 검사하는 `beforePress` 경로를 유지했다. 앱 버전은 1.1.4, `versionCode`는 21이다.

## 검증

- Node 18.20.4에서 블로그 삭제, 삭제 후 판독, 삭제 요청 방어, Surface hit 검사, 전송 로그 시험 5개 파일의 76개 시험을 통과했다. 합성 페이지에서 첫 PageDown 후 광고 iframe이 중앙과 가로 후보를 가릴 때 세로 후보로 넘어가 한 번만 삭제하고 URL과 목록을 다시 읽었다. 전체 후보가 iframe에 가린 경우와 중앙이 `body` 바깥의 덮는 층에 가린 경우에는 추가 키 입력과 클릭이 없었다. 스크롤 후보를 찾더라도 삭제 링크가 가려지면 클릭 없이 중단했다. 전송용 로그에서 허용 목록 적용을 확인했다.
- `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm check:secrets`, `git diff --check`를 통과했다. Node 18.20.4에서 내장 런타임 소스 117개를 검사했다.
- Android `gradlew.bat :buildSrc:test testDebugUnitTest testReleaseUnitTest assembleDebug --console=plain --offline`을 통과했다. buildSrc 10개, Debug·Release 각 23개의 단위 시험에서 실패·오류·건너뜀이 없었다. 디버그 APK의 `kr.goltou.auto`, 1.1.4(21), 내장 번들 2개와 소스 커밋을 확인했다.

- Node 18.20.4에서 `./scripts/install-device.ps1 -Variant release -VerifyOnly -ArtifactDirectory ../release-out`을 통과했다. `pnpm test`는 전체 110개 파일의 1,375개 시험을 통과했다. 필수 런타임 시험 6개가 포함됐고 건너뜀과 TODO는 각각 0개였다.
- `pnpm build`와 Android `assembleRelease`를 통과했다. 내보낸 릴리스 APK에서 `kr.goltou.auto`, 1.1.4(21), 내장 번들 2개, 소스 커밋과 v2·v3 서명을 확인했다. APK 실측 SHA-256이 `.sha256` 파일과 일치했고, 서명 인증서 지문은 직전 1.1.4(20) APK와 일치했다.
