# WP31 릴리스 연결 확인 복구

2026-11-17. PR #30 병합 main `5726f4b`에서 `codex/release-connect-fix`를 만들었다.
[지시서](../wp/WP31-release-connect.md)의 범위다. 기기 앱 삭제/초기화/debug 설치 금지,
네이버 저장·발행·밴드 게시·삭제 예산은 모두 0이다.

## 원인과 수정

기기 켜짐·잠금 해제·정식 앱 전면을 읽기만 하여 확인하고 1.0.0 (3)의 오류를 재현했다.
승인된 adb WebView 채널에서 비밀 없는 문서 이동과 오류만 관찰했다.

1. 밴드 확인은 `band.us/` → `www.band.us/` HTTP 200까지 성공했다.
2. 페이지가 scriptInitiated로 `www.band.us/about/kr/intro`로 이동하려 했다.
3. 공통 로그인 navigation policy의 숨김 landing 목록에 이 주소가 없어 Kotlin
   `shouldOverrideUrlLoading`이 이동을 거부했다. 관찰한 문서 오류는 `net::ERR_ABORTED`였고,
   앱은 로딩 시간 초과를 일반 인터넷 오류로 표시했다.

R8/리소스 축소는 이미 false였다. DEBUG와 독립된 WebView 제어 채널은 WebView/Node 생성 전에
활성화됐고 실제 CDP 접속도 됐다. release/debug은 같은 native 프로필·network security·이동 정책을
쓴다. 따라서 release 전용 최적화 결함이 아니라 **새 비로그인 프로필에서만 지나가는 경로 누락**이다.
이전 debug 세션이 인증 상태였기 때문에 드러나지 않았다는 설명은 정황에 따른 추정이며,
삭제된 이전 debug 앱의 private 데이터는 읽지 않았다.

- 관찰한 정확한 `/about/kr/intro`만 숨김 landing에 추가했다. 로그인 화면으로 표시하지 않으며
  편집기·피드·다른 소개 경로 차단을 유지한다. 계정별 naver/band 프로필은 바꾸지 않는다.
- release에도 `GOLTOU-CONNECT` native logcat을 남긴다. 생성/이동 시작·완료/정책 차단/
  WebView 네트워크·HTTP 오류/표시·숨김/renderer 종료와 서비스·허용 host/path·숫자 코드만 쓴다.
  query·fragment·raw 예외·페이지 내용·계정·쿠키·인증 헤더는 출력하지 않는다.
- 코어 로그는 실제 실패 사유를 terminal까지 보존한다. 비로그인 판독은 정상 완료로 기록하고
  `LOGIN_REQUIRED`를 남긴다. 모든 실패를 인터넷 오류라고 단정하는 배너를 일반 재확인 안내로 바꿨다.
  기존 로그 내보내기도 유지한다.
- 버전을 1.0.0 (4)로 올렸다. 서명 키와 설정은 저장소 밖 기존 파일을 사용한다.

네이버 Blog 로그인 버튼은 수정 전 1.0.0 (3)에서도 실제 네이버의 빈 로그인 폼이 표시됐다.
아이디·비밀번호·앱 열기·서비스 로그인 버튼은 누르지 않고 앱의 돌아가기/취소로 복귀했다.
소유자의 이전 일시적 Blog 오류는 같은 원인이라고 단정하지 않는다.

## 검증

- 새 release 컴파일/Chromium 회귀시험: 새 Band 프로필의 홈페이지 → 소개 페이지 script 이동을
  재현하고 native와 같은 allowed/landing 경계를 적용한다. `expired` 판독·밴드 로그인 화면·
  네이버 로그인 화면을 검증한다. DNS를 차단하고 모든 서비스 응답은 로컬 대역으로 공급한다.
- TypeScript 단위시험: 소개 경로는 landing, 하위·다른 경로는 차단; 실패 사유 보존과 비로그인 완료.
- Android debug/release 단위시험: 로그 query·식별자 제거와 범위 밖 코드 제거, 숨김 landing 경계.
