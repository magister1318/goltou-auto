# WP47 블로그 번호 줄에서 이모지 입력 중단 수정

## 변경

- Android 버전을 1.1.3(17)에서 1.1.4(18)로 올렸다.
- 11월 20일 S24(SM-S928N)와 S25(SM-S931N)에서 상품 1387로 관측한 동작을 재현 조건으로 삼았다. SmartEditor가 보조 평면 이모지와 다른 문자를 한 번에 받으면 이모지만 남겼다. 기존 코드는 번호 표식부터 최대 32글자소까지 같은 `insertText`에 넣었다.
- `BlogRichTextWriter`는 이제 `1. `, `- `, `a) ` 같은 표식만 한 번 입력하고 `readBlogCursor`로 즉시 확인한다. 표식이 유효한 문단 끝에 확인되면 나머지 내용을 기존 `typeText`로 입력한다. 표식에 걸친 굵기는 키보드 선택으로 반영하고, 링크는 원래 run 범위로 적용한다. 확인한 표식과 실제 굵기 상태를 진행 기록에 반영해 중단 지점부터 이어 쓴다.
- 표식 확인 실패 시 Ctrl+Z를 한 번 보낸다. 다시 읽어 표식을 확인할 수 없으면 `BLOG_FORMATTING_INPUT:N:input`으로 중단하며 저장과 발행으로 넘어가지 않는다.

## 묶음 입력 사용처

| 사용처 | 감사 결과 |
| --- | --- |
| `packages/sites/src/naver-blog/rich-text.ts`의 `BlogRichTextWriter.write` | 표식과 이모지를 섞을 수 있었던 앱 코드의 유일한 사용처였다. 지금은 표식만 원자적으로 입력한다. |
| `packages/surface/src/cdp/index.ts`의 `CdpSurface.typeText`와 `insertText` | `inputCharacters`가 나눈 글자소마다 CDP `Input.insertText`를 호출한다. |
| `apps/`, `packages/`, `scripts/`의 나머지 생산 코드 | 이모지와 본문을 한 호출에 섞는 사용처가 없었다. 합성 시험의 직접 호출은 시험용이다. |

## 진단 로그

`verification`의 실패 및 결정 줄과 WP46 전송본에 `blogInput`을 넣는다. 문자 수, 표식 길이와 일치 여부, 첫 세 코드 포인트의 종류, `.se-emoji` 개수, 목록 여부를 허용 목록으로 재구성한다. 텍스트나 링크 주소는 담지 않는다. 표식 확인의 단계는 `insert` 또는 `after_undo`다. 입력 기능이 없는 경우, 문단 끝, 기존 링크 창, 링크 버튼·주소 입력칸·확인 버튼·창 닫힘 확인에서도 고정 위치 이름과 관측 가능한 값을 기록한다.

아래는 실패 합성 시험에서 기록한 결정 줄의 필드 예시다. 이 시험에서는 표식 3자를 기대했으며 한 번의 실행 취소 뒤 목록 안에서 4자를 읽었다.

```json
{
  "step": "verification",
  "event": "decision",
  "choice": "fail",
  "check": "input",
  "reason": "READBACK_INPUT",
  "counts": {"expected": 3, "observed": 4, "paragraphIndex": 1},
  "blogInput": {
    "location": "marker_readback",
    "phase": "after_undo",
    "markerLength": 3,
    "observedCharacters": 4,
    "startsWithMarker": false,
    "firstCharacters": ["emoji", "hangul", "latin"],
    "emojiCount": 1,
    "inList": true
  }
}
```

## 검증

- 별도 작업 사본의 기준 커밋 `5371c9d`에 새 합성 시험과 편집기만 적용했다. 기존 32글자소 묶음에서 새 시험이 `BLOG_FORMATTING_INPUT:1:input`으로 실패했다.
- 수정본에서 `1. 💚 가성비 골프`, `2. ⛳ 골프`, `- 💚 a`, 표식에 걸친 굵기와 번호 줄의 링크를 입력하고 임시저장을 다시 열어 확인했다. 표식 직후 중단한 작업은 같은 편집기에서 표식을 중복 입력하지 않고 재개했다. 합성 편집기에서 공백 키의 목록 변환, Ctrl+Z 한 번 후 중단에 따른 실패·결정 로그와 로그 허용 목록을 확인했다.
- `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm build`, `pnpm check:secrets`, `git diff --check`를 통과했다.
- `pnpm test`에서 110개 파일의 1,363개 시험이 모두 통과했다. JSON 결과에서 필수 런타임 시험 6개, 건너뜀 0개, TODO 0개를 확인했다.
- Node 18.20.4에서 입력과 로그 관련 시험 9개, 실행 소스 115개 및 릴리스 번들 2개의 호환 검사를 통과했다. 긴 문단 시험에서 로그까지 기록하던 초기 실행은 시간 제한을 넘겼다. 기존 문단 시험을 유지하고 로그 검사를 짧은 사례로 분리한 뒤 두 시험을 모두 통과했다.
- Android의 `gradlew.bat assembleDebug --console=plain --offline`과 릴리스 게이트의 `assembleRelease`가 통과했다. 두 APK의 패키지 `kr.goltou.auto`, 버전 1.1.4, versionCode 18 및 내장 번들의 소스 커밋을 확인했다.
- `./scripts/install-device.ps1 -Variant release -VerifyOnly -ArtifactDirectory ../release-out`가 통과했다. 외부 배포 키로 서명한 APK를 내보낸 뒤 파일의 SHA-256과 체크섬 파일을 대조했다.
- 검증은 로컬 합성 편집기와 APK 검사로 수행했다. 실기기 1.1.4 입력과 설치는 미검증이다. 실제 게시 및 운영 접속은 수행하지 않았다.
