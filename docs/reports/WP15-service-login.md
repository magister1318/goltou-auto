# WP15. 서비스 로그인

기존에는 작업이 만든 WebView만 보여 줬다. 앱을 새로 켜면 화면이 없거나 빈 화면이었고, 작업 밖에서는 로그인 상태도 읽지 않았다.

로그인 전용 화면을 필요할 때 만들고 기존 `goltou-naver`·`goltou-band` 영구 프로필을 쓴다. 실제 로그인 페이지가 로드된 뒤에만 보여 준다. 실패·시간 초과에는 화면을 열지 않고 다시 열라는 오류를 표시한다. 네이버의 현재 계정 확인 경로 `myInfoV2`도 실기기에서 확인했다.

사용자가 겪는 순서는 다음과 같다.

1. 앱을 켜면 두 서비스를 숨겨서 차례로 확인한다. 잠깐 “확인 중”이 보인 뒤 “확인됨” 또는 “풀림”이 된다. 연결이나 확인에 실패한 때만 “모름”이 남는다.
2. 홈·설정·작업 중 재로그인 안내에서 연다. 이미 로그인돼 있으면 실제 로그인 화면을 표시하지 않고 원래 화면으로 돌아간다. 미로그인 상태라면 실제 서비스 페이지에서 사용자가 직접 로그인한다.
3. 1.5초 간격으로 로그인 표시만 읽는다. 성공하면 화면을 자동으로 닫는다. 돌아가기 버튼과 기기 뒤로가기는 취소이며, 숨긴 뒤 한 번 재확인한다. 작업 중에는 확인된 뒤 사용자가 “이어하기”를 누른다.
4. 골투 로그인 뒤와 5분 이상 다른 곳에 있다 돌아왔을 때 다시 확인한다. 진행 중인 작업이 있으면 미룬다. 로그인 화면을 여는 중·표시 중·확인 중에는 작업을 새로 시작하지 못한다.

인증 경로만 화면에 표시한다. 로그인 뒤 도착 페이지는 표시 전에 숨겨서 확인 페이지로 다시 검증한다. 편집기·밴드 피드·외부 주소·앱 링크·새 창은 차단한다. 자격증명·쿠키·본문을 수집하지 않는다. UI는 상태·오류·자동 복귀 안내만 최소 수정했다.

확인 명령: `pnpm install`, `pnpm typecheck`(내부 `pnpm -r typecheck`와 Android bridge 포함), 루트 `pnpm test`, `pnpm build`, Android `gradlew.bat testDebugUnitTest assembleDebug` 모두 통과. 루트 시험은 50파일·580개, Android 단위 시험은 4개 통과했다. 작업 중 네이버 경로 보완과 시험 타입 오류를 고친 뒤 전체를 다시 확인했다.

실기기: 2026-11-14 KST, 연결·화면 켜짐·전면 Activity와 현재 창을 읽어 확인했다. `adb install -r`로 기존 로그인을 유지했다. 최종 APK에서 UI를 처음 읽은 시점을 기준으로 네이버 2.124초, 밴드 5.032초에 자동으로 “확인됨”이 됐다. 그때까지 화면을 누르지 않았다. 이어서 홈의 네이버·밴드 안내를 각각 열었다. 안전 확인 시간을 포함해 안내 진입부터 각각 2.211초·3.657초에 홈으로 자동 복귀했고, 두 상태는 계속 “확인됨”이었다. 실제 서비스 화면은 표시되지 않았고 모든 관측에서 작업은 없었다. 앱은 설치된 채 홈에 남겼다.

미로그인 입력·추가 인증·동의·로그인 뒤 자동 숨김·취소·네트워크 실패·시간 초과·금지 주소·작업과의 충돌·장시간 복귀는 단위/브라우저 fixture로만 확인했다. 실기기에서 로그아웃·프로필 삭제·서비스 페이지 입력·작업 실행은 하지 않았다. 설정에서 여는 공통 엔진 경로는 fixture로 확인했으며 실기기 안내 확인은 홈에서 했다. 전체 화면 개편과 실제 미로그인 계정 시험은 이번 범위 밖이다.
