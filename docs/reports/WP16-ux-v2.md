# WP16 UX v2 — 잔여 글 정리와 진행 화면 후속 확인

사용자는 상품 미리보기에서 블로그 임시저장을 시작하고, 앱이 그리는 진행 화면에서 실제 글·사진·확인 결과를 볼 수 있습니다. 저장한 글을 다시 읽어 대조한 뒤에는 검증용 편집기를 닫습니다. 앱이 마지막으로 입력한 제목은 기기 안에만 보관하며, 복구 안내에서 읽은 제목과 정확히 같을 때만 기존 “버리고 새로 쓰기” 처리로 자동 정리하고 짧은 안내를 보여 줍니다. 제목이 다르거나 읽히지 않으면 선택 시트를 유지합니다.

**이번 두 실행 중 run3는 저장 뒤 같은 제목의 임시글이 여러 개여서 재열람 대상을 확정하지 못했고, run4는 선택 시트 없이 시작해 약 198초 만에 임시저장·재열람을 완료했습니다.** 두 번 연속 정상 완료한 뒤 안내가 사라지는 조건 전체는 확인하지 못했습니다. 실제 발행·밴드 게시·글 삭제는 하지 않았습니다. 현재 네이버 복구 안내는 잔여 글의 제목을 표시하지 않으므로, 자동 제목 판정은 합성 화면에서 확인한 범위입니다.

## 소유자 결정과 적용 범위

- 2026-11-14 20:44 KST 결정: “앱이 남긴 것만 자동 정리”. 제목의 완전 일치만 인정하고 공백 제거·부분 일치·현재 상품 제목 추측은 하지 않습니다.
- 시작 전 화면 켜짐, 앱 창 포커스, 최상단 실행 앱을 읽기 전용으로 확인했습니다. 처음 읽은 화면은 이전 작업의 완료 화면이었습니다. 대기 중이던 작업으로 오인해 버튼을 누르지 않고 새 임시저장 run3를 시작했습니다.
- 이번 세션의 시작 입력은 run3와 run4, 두 번뿐입니다. 실패한 run3를 다시 저장하거나 재시도하지 않았습니다. run4는 아직 올리지 않은 다른 상품으로 실행했습니다. 두 실행 모두 잔여 글 시트가 나타나지 않아 버리기 입력은 없었습니다.
- 잔여 글은 복구 안내에 드러난 제목만 읽습니다. 제목을 보기 위해 복구 확인을 누르거나 본문·자동저장 응답·계정 상태를 수집하지 않습니다. 현재 실제 안내처럼 제목이 없는 경우는 사용자가 선택해야 합니다.
- 제목은 셸이 제공한 앱 전용 파일 `last-blog-title.txt` 한 곳에 덮어씁니다. 기기 파일의 권한 600과 존재만 확인했고 내용은 꺼내지 않았습니다. 제목·계정·상품 원문·게시글 주소를 저장소나 보고서에 넣지 않았습니다.

## 반복 안내의 원인과 수정

실제 편집기가 불러온 공개 정적 코드에서 임시저장, 자동저장, 발행, 이탈 처리를 대조했습니다. 정적 파일은 저장소 밖 `..\runs\wp16-static\`에만 보관했습니다.

네이버는 문서 변경 신호 뒤 약 3초 지연으로 `RabbitAutoSaveWrite.naver`를 요청합니다. 임시저장함의 글을 다시 불러오는 동작도 문서를 설정합니다. 기존 앱은 저장한 글의 대조를 마친 뒤에도 그 편집기를 열어 두었으므로, 재열람용 문서가 다시 자동복구 글을 남길 수 있었습니다. 임시저장 완료 표시와 자동복구 글의 부재는 같은 조건이 아니었습니다. 이탈 핸들러는 작성 중 경고를 담당하며, 편집기를 닫는 것만으로 이미 저장된 자동복구 글이 삭제된다고 볼 수 없습니다.

- 재열람용 화면은 **열기 전에** 자동저장 쓰기 요청을 차단합니다. 임시저장 요청, 원문 대조, 발행 시 단 한 번의 제출 및 응답 검증 장치는 유지합니다. 발행을 준비하는 재열람 화면에도 같은 차단이 적용됩니다.
- 완료 처리에서 성공한 블로그 편집기를 닫아 지연 작업이 계속 남지 않게 했습니다. 중단·실패한 편집기는 이 성공 정리 대상에 넣지 않습니다. 닫기는 마지막 정리 단계에 두어, 중단 후 이어하기가 이미 닫힌 편집기를 다시 읽지 않도록 했습니다.
- 이미 있던 자동복구 글은 별도 삭제 요청으로 지우지 않습니다. 제목이 확인되면 기존 복구 취소 클릭 경로를 공유합니다. 저장된 임시글이나 발행된 글을 삭제하는 요청은 추가하지 않았습니다.
- 로컬 편집기 시험은 임시글 재열람 뒤 실제 지연 요청을 발생시켜 차단을 확인하고, 저장된 임시글은 남으며 다음 편집기는 동의 시트 없이 열리는지 검사합니다. 기기 run4 완료 후 블로그 편집기 화면이 0개인 것도 확인했습니다.

표본은 1초 일정으로 읽었고 실제 최장 간격은 run3 1.132초, run4 1.196초입니다. PNG는 약 5초마다 찍고 마지막 결과를 따로 남겼습니다. 표시 정체는 단계 안내·응답 대기 표시·막대의 화면상 길이·표시 글자 수·사진 수·확인 표시를 비교하며, 전체 경과/남은 시간 시계만 움직인 것은 작업 변화로 세지 않았습니다. 선택 대기는 두 실행 모두 0초였습니다. 완료 화면으로 전환되어 진행 내용이 사라지는 것은 후퇴로 세지 않습니다. 두 실행에서 새 진행 표시 결함은 발견하지 않았습니다.

run3의 실패 코드는 `DRAFT_IDENTITY_AMBIGUOUS`입니다. 저장 뒤 같은 제목 목록이 여러 개라 안전하게 멈췄습니다. 어떤 항목을 임의로 고르거나 저장을 다시 누르지 않았습니다. 이 중복 제목 문제는 이번 잔여 글 정리 변경으로 해결됐다고 보고하지 않습니다.

원본은 모두 저장소 밖 `..\runs\wp16-shots\`에 있습니다.

- `progress-metrics-3.json`, `run3-XX.png`, `run3-ended.png`: 실패 실행. `run3-done.png`는 만들지 않았습니다.
- `progress-metrics-4.json`, `run4-XX.png`, `run4-done.png`: 완료 실행.

## 확인 명령과 범위

최종 전체 자동 시험은 **610개 통과·0개 실패·0개 건너뜀(56개 파일)**입니다. [집계 파일](wp16-ux-v2/verification.json)에 내용 없는 수치만 남겼습니다. 전체 결과와 선택 실행의 제외 수를 합산하지 않습니다.

- `pnpm install`: 통과, 잠금 파일 변경 없음.
- `pnpm typecheck`: 통과. 추가한 선택 속성의 타입 오류 1건을 고친 뒤 다시 통과했습니다.
- `pnpm test --reporter=verbose --reporter=json --outputFile=tmp/wp16-owner-final-tests.json`: 610개 통과·0개 실패·0개 건너뜀.
- 마지막 정리 단계와 제목 읽기 실패 처리의 후속 선택 시험: 6개 통과·0개 실패·20개 제외. 전체 시험 수가 아닙니다.
- `pnpm build`: 통과, Node 18 대상.
- `apps/android`에서 `./gradlew.bat assembleDebug --console=plain`: 통과.
- `git diff --check`: 통과.

제목 읽기 자체가 실패한 경우의 후속 시험도 1개 통과·0개 실패·0개 건너뜀입니다.

제목 완전 일치 자동 정리, 다른 제목·빈 제목·저장 기록 부재의 동의 대기, 로컬 제목 파일 재사용, 진행 화면의 짧은 안내 유지, 재열람 자동저장 차단, 완료 후 편집기 닫기를 합성 화면/로컬 파일 시험으로 확인했습니다. 기존 발행 차단·단일 제출·응답 검증 시험도 전체 시험에 포함합니다. 실제 서비스에서 자동 제목 판정·발행·삭제를 수행했다는 뜻은 아닙니다.

최종 APK도 화면 켜짐·앱 창 포커스·최상단 앱을 읽기 전용으로 재확인하고 `adb install -r`로 설치했습니다. 깨우기나 잠금 해제 없이 골투오토만 열어 상품 목록을 확인했고 그 화면에 두었습니다. `final-product-list.png`는 저장소 밖에 있습니다.

## 기존 WP16 화면 작업

미리보기의 임시저장/발행 분리, 발행 확인, 진행/완료/실패, 계정 연결, 등록 기록, 설정, 작업 중 중단 확인, 로그인 복귀 흐름은 앞 회차의 48장 시뮬레이터 화면과 기기 확인을 유지합니다. 밴드 목록 조회와 마지막 선택, 세 글 옵션의 로컬 보관, 앱이 그리는 진행 화면, 화면 켜짐 유지, 확인 표시 재검증 때의 후퇴 방지를 포함합니다. 이번 변경 때문에 모든 기본 화면을 다시 촬영했다고 주장하지 않습니다.

이전 보고서의 596개 전체 통과 표기는 철회된 상태를 유지합니다. 당시 실제 결과는 513개 통과·83개 건너뜀이었고, 그 뒤 회차의 604개 및 607개 전체 통과 결과와도 이번 결과를 합치지 않습니다.

## 남은 확인과 다음 작업

1. 두 번 연속 정상 완료한 뒤 다시 시작하는 조건 전체는 미확인입니다. run3의 같은 제목 중복 때문에 충족하지 못했으며, 최대 두 실행 규칙을 지켜 추가 실행하지 않았습니다. 저장 결과를 제목 외의 확실한 기준으로 구분하는 개선이 필요합니다.
2. 현재 실제 네이버 복구 안내는 제목을 드러내지 않습니다. 제목 일치 자동 정리는 합성 화면 범위이며, 실기기에서 제목이 읽히지 않을 때 동의 시트를 유지하는 정책을 적용합니다.
3. 발행 뒤 정리·실제 밴드 게시·블로그 발행/삭제·로그인 변경·앱 배경 전환은 이번 실제 계정 시험 범위 밖입니다. 공개 정적 코드와 합성 화면의 결과를 실제 발행 성공으로 쓰지 않습니다.
4. run4 이후 최종 빌드에서는 완료 편집기 닫기를 마지막 정리 단계로 옮기고, 제목 읽기 오류도 동의 대기로 처리했습니다. 이 마지막 두 안전 조정은 후속 자동 시험으로 확인했고 추가 기기 임시저장은 하지 않았습니다.

PR #19는 초안으로 유지합니다. 운영 서버/DB 직접 작업, 운영 반영, main 직접 푸시는 하지 않았습니다.
