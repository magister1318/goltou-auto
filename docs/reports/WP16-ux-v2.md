# WP16 UX v2 화면 재구성 및 밴드 직접 게시

사용자는 상품을 찾고, 블로그·밴드에 올라갈 모습을 확인한 뒤 나란히 있는 임시저장·발행 버튼으로 옮길 수 있습니다. 임시저장은 블로그만 대상으로 합니다. 발행 시트에서 올릴 곳·밴드·블로그 공개 범위를 고르고 한 번 더 확인합니다. 옮기는 동안 실제 입력 계획의 글·사진과 엔진의 확인 결과를 앱 화면에서 봅니다. 계정 연결, 등록 기록, 글 보기·블로그 글 삭제, 설정도 새 화면으로 정리했습니다.

**밴드 직접 게시의 제출·응답·글 식별 검증은 로컬 fixture에서만 확인했습니다.** 시험 APK의 실제 밴드 게시 기능은 차단합니다. 실기기 발행 시트에서는 밴드 목록을 확인하지 못해 다시 확인 안내까지 확인했습니다. 실제 밴드 이름 선택은 fixture 검증 범위입니다. 실제 밴드의 요청·응답 형식과 사진 업로드 경로는 별도 승인을 받은 실계정 시험 전까지 검증되지 않았습니다. 알려진 형식 밖 요청은 허용하지 않습니다. 시뮬레이터 사진과 내용은 합성 예시입니다. 글 옵션의 켜짐 여부는 현재 앱 실행 중 적용되며 앱을 다시 열면 기본 꺼짐입니다. 문장 다듬기 수준은 기존 개인 저장 설정을 사용합니다.

**실기기 블로그 임시저장은 한 번 시작했지만 끝까지 완료 검증하지 못했습니다.** 네이버에 기존 작성 중인 글이 있어 `AUTO_RECOVER_CONSENT_REQUIRED`에서 멈췄습니다. 이전 글을 버리지 않았고, 이어하기·재실행·발행·게시·삭제도 하지 않았습니다. 실기기 진행 캡처는 준비 화면 1장과 중단 화면 1장이며, 글·사진 입력부터 임시저장 재열람까지 여러 단계의 실제 캡처는 확보하지 못했습니다.

## 구현

- 승인 목업 HTML의 스크립트와 화면별 설명을 읽고, Chromium에서 화면 11개와 시트 5개를 모두 눌러 확인했습니다. 외부 글꼴 요청을 차단한 로컬 브라우저로 확인했습니다.
- 상품 목록에 연결 상태, 검색, 전체/안 올린 상품, API 사진·가격·출발일 수와 채널별 등록 상태를 표시합니다. 미리보기의 본문·사진 순서는 기존 변환 계획을 사용합니다.
- 임시저장·발행·발행 확인·중단 확인·삭제 확인 시트를 구현했습니다. 발행을 새로 열 때 블로그 공개 범위는 전체공개입니다. 옵션 기본값은 모두 꺼짐입니다.
- 로그인 필요·연결됨·확인 중 상태를 표시하고 확인 실패에는 설명과 다시 확인 동작을 제공합니다. 로그인은 WP15의 별도 제한된 서비스 화면을 사용하며, 완료 후 원래 화면·시트 또는 멈춘 작업으로 돌아옵니다.
- 작업용 웹 화면을 여는 일반 UI와 코어 명령 경로를 막았습니다. 안드로이드에서도 로그인 이동 제한 정책이 없는 surface의 표시를 거부합니다. 정상 탐색에는 실험·진단 메뉴가 없습니다.
- `post.open`은 기기 기능 인터페이스를 거쳐 Android `ACTION_VIEW`로 연결합니다. 숨긴 작성 화면을 열지 않습니다. 실제 외부 앱 실행은 이번 기기 시험에서 하지 않았습니다.
- 진행 프로토콜에 채널, 단계, 블록 종류·위치·수, 사진 위치·수·비율, 검증 항목 시작·완료, 저장/발행 구분을 추가했습니다. 이벤트에는 페이지 본문·계정 정보가 없습니다. 원문은 앱이 이미 가진 입력 계획에서 표시합니다.
- 입력 순서대로 글이 채워지고 사진은 실제 첨부 확인 뒤 썸네일로 바뀝니다. 검증 표시는 엔진에서 실제 통과한 항목만 표시합니다. 블로그→밴드, 사진 칸, 검증 표시, 진행률·경과 시간·남은 시간 추정이 있습니다. 진행률은 뒤로 가지 않으며 완료 전에는 100%가 되지 않습니다. 관측할 수 없는 구간은 추정으로 움직입니다.
- 완료된 블록 시간과 사진 업로드 측정값을 사용합니다. 반복되는 진행 신호는 합쳐 장문에서 상태가 계속 커지지 않게 했습니다. 동작 줄이기를 존중하고, 화면 복원은 작업 상태와 그 작업의 저장된 입력 계획을 사용합니다.
- 작업 중 앱 창의 `keepScreenOn`만 설정합니다. 휴대폰을 깨우거나 잠금 해제하는 기능은 추가하지 않았습니다.
- 밴드 surface의 첫 이동 전에 네트워크 차단을 설치합니다. 읽기 요청과 제한된 사진 업로드 외 쓰기는 제출 전 차단합니다. 제출 시 선택한 밴드, 버튼 위치, 요청 대상, 한 번의 요청, 성공 응답과 게시글 식별자·재열람 내용을 확인합니다. 불확실한 결과는 재게시하지 않습니다. 게시 후 기록 실패도 기록만 다시 시도합니다.
- 과거 밴드 게시 전 멈춤 시험은 저수준 회귀 fixture로 남아 있지만, 앱의 임시저장 요청에 밴드를 넣으면 상품 조회·기록 생성 전에 거절합니다. 작업 surface를 보여 주는 앱 경로도 차단합니다.

## 사용자 안내 매핑

오류 원문이나 코드는 사용자 화면에 노출하지 않습니다. 상세 코드는 내부 기록에 남깁니다.

| 코드/상태 묶음 | 안내 내용 |
| --- | --- |
| 사진 내려받기·네트워크·시간 초과 | 공개 여부를 먼저 알리고 연결 확인·다시 시도를 안내 |
| 읽어 온 내용 불일치 | 공개 여부와 원문이 달라 중단한 사실, 기록 확인 안내 |
| 글·사진 제한 | 공개 여부와 제한 초과 사실, 기록 확인 안내 |
| 버튼·편집기·surface 오류 | 공개 여부와 평소와 다른 글쓰기 화면, 다시 시도 안내 |
| 기록 저장 실패 | 확인된 채널 결과를 유지하고 기록만 다시 시도 |
| 제출 후 결과 불명확 | “게시됐는지 확인하지 못했습니다.”와 해당 서비스 확인·재게시 금지 안내 |
| 그 밖의 오류 | 공개 여부, 끝까지 옮기지 못한 사실, 기록 확인·담당자 문의 안내 |

제출 이후에는 별도 불확실 상태를 유지해 일반 시간 초과가 “공개되지 않음”으로 잘못 표시되지 않게 했습니다. 일부 채널이 먼저 발행된 경우 해당 결과도 유지합니다.

## 실기기

- 지정 기기에서 설치 직전 `dumpsys power`의 켜짐 상태, `dumpsys window`의 앱 포커스·focused activity, activity의 최상단 실행 상태를 읽기 전용으로 확인했습니다.
- `adb install -r` 성공. 마지막 수정 APK도 같은 사전 확인 뒤 다시 설치했으며, 추가 임시저장 실행은 하지 않았습니다. 패키지 갱신 전환이 끝나고 골투오토가 전면으로 돌아온 것을 확인한 뒤 이 앱에만 입력했습니다. 깨우기·잠금 해제·다른 앱 조작은 하지 않았습니다.
- 상품 목록, 미리보기, 임시저장 시트, 발행 시트, 계정 연결, 등록 기록, 설정의 **7개 화면 확인 통과**. [`wp16-ux-v2/device/`](wp16-ux-v2/device/)에는 화면 캡처의 계정·상품 영역을 불투명하게 가린 이미지 9장만 둡니다. 원본과 좌표는 저장소 밖 임시 폴더에서만 처리한 뒤 삭제했으며 텍스트 추출을 하지 않았습니다.
- 실기기 임시저장 **1회 시작·1회 중단**, 완료 확인 0회. 기존 작성글 보호 단계에서 멈췄으므로 재실행하지 않았습니다. 자동화 스크립트는 버튼 입력 전에 1회 실행 표식을 저장소 밖에 남깁니다.
- 실기기 **미실행 3건**: 블로그 실제 발행, 밴드 실제 게시, 외부 앱으로 글 보기. 앞의 둘은 지시서 금지 사항이고 마지막은 앱 밖 조작 금지 범위를 지키기 위해 실행하지 않았습니다. 실제 글 삭제도 하지 않았습니다.
- 로그인 필드 값·비밀번호·서비스 쿠키를 읽거나 입력하지 않았습니다. 계정 식별자·상품 문구·실제 게시글 주소는 보고서와 검증 로그에 넣지 않았습니다.

## 다음 검토에 넘길 점

1. 사용자가 기존 네이버 작성글을 직접 정리한 뒤 별도 작업에서 실기기 임시저장 전체 흐름을 확인해야 합니다. 이번 작업의 1회 제한 때문에 추가 실행하지 않았습니다.
2. 실제 밴드 게시 시험은 별도 소유자 승인 후 진행해야 합니다. 현재 fixture 계약 밖 요청·응답은 중단하며, 시험 APK는 실제 밴드 제출을 허용하지 않습니다.
3. 외부 앱 글 보기, 실제 계정의 연결 해제와 로그인 재개, 작업 중 앱 배경 전환은 fixture/코드 및 빌드 검증 범위입니다. 기기의 기존 계정 상태를 바꾸거나 다른 앱으로 나가지 않았습니다.
4. 검토용 초안 PR이며 운영 서버·DB 작업, 운영 반영, main 직접 push는 하지 않았습니다.
