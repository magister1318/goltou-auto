# WP16 UX v2 — 중복 제목 임시저장 확인과 진행 문구 수정

같은 상품을 다시 임시저장할 때 기존 글과 제목이 같아도, 방금 저장한 항목을 구별해 다시 읽고 원문을 확인합니다. 저장은 확인됐지만 다시 열 대상을 확정하지 못하면 **“임시저장은 됐지만 내용을 다시 확인하지 못했습니다”**라고 안내하고 별도 결과를 남깁니다. 진행 화면 보조 문구의 의미 없는 초 표시도 없앴습니다.

실기기 run5는 같은 제목의 기존 임시글 **1개**가 있는 상품으로 **한 번만** 실행해 저장·재열람 검증을 완료했습니다. 저장 전후 목록 차이로 새 항목을 확정했고, 약 **195.391초**가 걸렸습니다. 쓰다 만 글 시트는 나오지 않았습니다. 완료 화면과 상품 목록을 확인했으며 상품 목록에 두었습니다. 실제 발행, 밴드 게시, 글 삭제, 로그인 입력은 하지 않았습니다.

## A. 방금 저장한 임시글 구별

- 저장 버튼을 누르기 전에 임시저장함의 제목·저장 시각·화면이 제공하는 식별자를 메모리에서 읽고 목록을 닫습니다. 상품 입력이나 저장을 다시 실행하지 않습니다.
- 이번 저장 요청의 성공 응답과 식별자를 메모리에서만 확인합니다. 화면에서도 같은 식별자를 확인할 수 있으면 그 항목을 사용하고, 그렇지 않으면 저장 전에는 없었던 제목·저장 시각 조합이 정확히 하나인 경우만 사용합니다. 실제 run5는 후자의 경로입니다.
- 제목 하나만 보고 고르거나 같은 후보 중 첫째·최신 항목을 추측하지 않습니다. 후보의 목록 위치를 정한 뒤에도 마우스를 누르기 직전에 전체 목록이 바뀌지 않았는지 다시 읽습니다. 항목을 연 뒤에는 기존 제목·본문·사진 순서·숫자·해시태그 대조를 그대로 수행합니다.
- 저장 성공 응답은 왔지만 목록이 그대로이거나 후보가 동등하면 `draft_unverified`로 끝냅니다. 완료 검증 단계는 표시하지 않고, 재저장·발행·밴드 진행도 하지 않습니다. 안내는 네이버 임시저장함에서 저장 시각과 내용을 직접 확인하도록 합니다.
- 서버의 기존 상태 계약은 바꾸지 않았습니다. 등록 기록에는 `stopped`와 `failReason: BLOG_DRAFT_SAVED_UNVERIFIED`를 함께 보내 구분하고, 앱에서는 **“임시저장 · 내용 재확인 못함”**으로 표시합니다. 실패/재시도 버튼 대신 등록 기록과 상품 목록으로 이동할 수 있습니다. 저장 성공 자체도 확인되지 않으면 저장 여부가 불확실하다고 안내합니다.
- 제목, 저장 시각, 임시글 식별자, 응답 원문은 기록하지 않습니다. 진단에는 기존 같은 제목 항목 수와 구별에 사용한 방식만 남깁니다. 발행 요청 차단과 재열람 자동저장 차단도 유지합니다.

## B. 진행 보조 문구

문단·사진·제목·해시태그 입력, 준비/응답 대기, 저장, 재열람, 확인 항목, 블로그/밴드 및 선택 대기 문구에서 단계별 초 표시를 제거했습니다. 문단 번호, 사진 번호와 진행률, 확인 항목은 유지합니다. 전체 진행 막대 아래의 실제 작업 경과 시간과 남은 시간은 유지하며 선택 대기 시간은 제외합니다.

실제 문단 화면에서 번호만 표시되는 것을 열어 확인했습니다. run5의 진행 표본 전체에서도 보조 문구에 `· N초`가 붙은 경우는 **0건**이었습니다.

## 확인 명령과 범위

최종 전체 시험은 **640개 통과·0개 실패·0개 건너뜀(57개 파일)**입니다. [수치 집계](wp16-ux-v2/verification.json)에 이전 회차와 구분해 남깁니다.

- `pnpm install`: 통과, 잠금 파일 변경 없음.
- `pnpm typecheck`: 통과.
- `pnpm test --reporter=dot --reporter=json --outputFile=tmp/wp16-run5-final-tests.json`: 640개 통과·0개 실패·0개 건너뜀.
- `pnpm build`: 통과, Node 18 대상.
- `apps/android`에서 `./gradlew.bat assembleDebug --console=plain`: 통과.
- `git diff --check`: 통과.

추가/변경한 합성 시험은 기존 같은 제목 임시글, 저장 응답 식별자 누락, 목록 불변, 같은 저장 시각 후보, 응답 식별자 충돌, 저장 미확인 응답을 다룹니다. 두 실행기의 저장됨·재확인 못함 상태와 API 기록, 이어하기 거절, 밴드 진행 금지도 확인합니다. 진행 보조 문구의 모든 분기와 전체 경과 시간 유지도 확인합니다. 처음 전체 실행에서 시험의 화면 캡처 예상 횟수 1곳이 잘못돼 실패했고, 기존 정상 저장의 증거 캡처를 인정하도록 고친 뒤 해당 선택 시험은 1개 통과·27개 제외였습니다. 최종 전체 결과와 이 선택 시험 수를 합산하지 않습니다.

## 이전 실행과 남은 확인

- run3는 같은 제목 중복 때문에 재열람 대상을 확정하지 못했습니다. 이번 수정으로 다룬 문제이며 run5로 실제 중복 조건을 확인했습니다. run4는 다른 상품으로 198.260초에 완료했던 이전 실행입니다. 이번 실제 실행은 run5 한 번뿐입니다.
- 이전 회차 전체 시험 610개 통과·0개 실패·0개 건너뜀 결과와 이번 결과를 합산하지 않습니다. 더 이전의 잘못된 596개 전체 통과 표기도 철회 상태를 유지합니다. 당시 결과는 513개 통과·83개 건너뜀이었습니다.
- 저장 뒤 검증용 편집기의 자동저장 요청 차단과 완료 후 마지막 단계에서 편집기 닫기는 유지합니다. 앱이 기억한 제목과 복구 안내에 실제로 보이는 제목의 완전 일치에 따른 자동 정리는 기존 합성 시험 범위입니다. 현재 실제 복구 안내는 제목을 드러내지 않으며, 이번 실행에서는 그 시트가 나오지 않았습니다.
- 같은 제목과 같은 저장 시각 때문에 구별하지 못하는 경우 및 목록 불변 안내는 합성 시험으로 확인했습니다. 실제 서비스에서 그 조건을 만들기 위한 추가 저장은 하지 않았습니다.
- 실제 블로그 발행·밴드 게시·삭제·로그인 변경·앱 배경 전환은 이번 기기 확인 범위 밖입니다. 운영 서버/DB 직접 작업과 main 푸시는 하지 않았습니다.
