# WP44 밴드 게시 사진 순서 확인

## 원인과 근거

- 제보된 1.1.0의 밴드 게시물 5267(운영 기록 68)은 본문과 링크 등을 확인한 뒤 사진 확인에서 `66/0`, 재시도에서 `66/66` 실패를 남겼다. 두 번째 실패는 `verifyFullBandPost`의 업로드 대 API 비교 또는 API 대 콜라주 비교에서 발생할 수 있다. API 없이 전체 DOM 사진을 읽은 경우에는 업로드 대 DOM 비교에서도 발생할 수 있다. 당시 로그의 `VERIFICATION_MISMATCH`로는 어느 비교가 실패했는지 알 수 없다.
- 이전 실기기 녹화 `g-band-publish-context.json`의 작성기 업로드 완료 슬롯 29개와 `g-read-response-shape.json`의 같은 글 피드 API `attachment.photo` 앞 10개를 대조했다. 작성기 주소는 HTTPS `coresos-phinf.pstatic.net`, 피드 API 주소는 HTTP `coresos.phinf.naver.net`이었고, 앞 10개의 전체 경로와 상대 순서는 일치했다. 이 녹화에는 업로드 HTTP 응답 원문과 상세 API의 첨부 배열이 없다. 앱이 비교에 실제로 사용하는 업로드 값은 작성기 이미지의 `currentSrc` 또는 `src`다.
- `g-detail-photos-proof.json`의 상세 이미지 경로 29개도 위 작성기 슬롯과 같은 순서로 일치했다. 다른 글의 `i-actual-full-private.json`에서는 상세 이미지 29개에 `type=e1920_std` 쿼리가 있었다. WP43의 5265번 글 조사에서는 같은 CDN을 쓰는 콜라주 `<img>` 31개와 사진 수 속성이 없는 구조를 확인했다. 기존 코드도 호스트와 쿼리를 제외하고 경로를 비교하므로, 이 두 차이만으로 5267번 글의 `66/66` 실패를 설명할 수 없다.
- 5267번 글의 업로드 슬롯·상세 API·콜라주 URL을 서로 대조할 수 있는 녹화는 찾지 못했다. 크기 표식이 쿼리에 붙은 사례는 확인했고, 표식이 경로 접미사로 붙은 실기기 사례와 실제 순서 변경 여부는 확인하지 못했다. 접미사를 경로에 넣은 시험은 그 형태가 들어올 때의 동작을 확인하는 합성 시험이다.

## 변경

- 작성기, 상세 API, 화면 이미지에 같은 사진 경로 비교 규칙을 적용한다. 호스트·프로토콜·쿼리를 제외하고 디렉터리와 원본 파일명을 유지한다. 조사에서 확인한 두 CDN 호스트에서 기존 사진 파일명 구조와 `e<숫자>_std` 크기 표식이 맞을 때만 경로 접미사를 제거한다. 다른 파일명과 폴더 차이는 검증에서 감지한다.
- API의 전체 첨부 목록을 업로드 순서와 위치별로 대조하고, 표시된 콜라주 사진은 API 순서의 부분 수열인지 확인한다. 개수 실패와 게시 결과 처리 방식은 유지한다.
- `photo_order` 실패에서 `UPLOAD_PATH_MISMATCH`와 `DOM_ORDER_MISMATCH`를 구분한다. 인덱스는 1부터 세며, 앞의 사유는 업로드 위치, 뒤의 사유는 DOM 슬롯 위치다. DOM 실패의 API 비교 경계는 아직 대조하지 않은 첫 항목이며, API 끝을 지난 경우 마지막으로 맞은 항목이다. 양쪽에 허용된 CDN 호스트, 확인된 파일명 끝 8자, 경로 크기 접미사 유무만 기록한다. 원본 URL·쿼리·쿠키·토큰을 기록하지 않으며 기존 512KB 전송 상한을 적용한다.
- Android 버전을 `1.1.1`(versionCode `15`)로 올렸다.

## 검증

- Node 18.20.4에서 사진 경로, 상세 API 판독, 순서 진단과 전송 로그를 확인하는 WP44 관련 시험 6개를 통과했다. 이전 녹화에 수정한 정규화를 적용해 피드 앞 10장과 상세 DOM 29장의 순서가 작성기와 일치함을 다시 확인했다.
- 오프라인 전체 게시 흐름에서 작성기 66장, API 66장, 건너뛰어 표시한 콜라주 31장을 대조해 확인 완료로 처리했다. API 65장 사례는 게시 주소를 유지하고 사진 1장 누락으로 기록했다. 두 사례 모두 업로드용 로그가 64,000바이트 미만이었고 잘림 표식이 없었다. 별도 시험으로 API 순서 변경과 콜라주 순서 변경이 각각 첫 불일치 위치에서 실패하고 URL·쿼리·쿠키·토큰이 로그에 남지 않음을 확인했다.
- `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm build`를 통과했다. Node 18.20.4에서 `scripts/check-embedded-compat.mjs`로 실행 소스 112개와 번들 2개를 확인했다.
- `apps/android`의 `gradlew.bat assembleDebug --console=plain --no-daemon --offline`이 통과했다. APK 메타데이터에서 패키지 `kr.goltou.auto`, 버전 `1.1.1`, 코드 `15`를 확인했다.
- `pnpm test --maxWorkers=4`에서 109개 파일의 1,343개 시험이 모두 통과했다. `scripts/check-test-report.mjs`에서 필수 런타임 시험 6개를 포함하고 건너뜀과 TODO가 각각 0개임을 확인했다. `pnpm check:secrets`와 Git 변경 검사도 통과했다.

## 남은 확인

- 5267번 글에서 어느 비교가 실패했는지와 실제 상세 API 및 콜라주 주소의 차이는 미확인이다. 이후 실기기 로그에서 `photo_order`의 사유와 첫 불일치 위치를 대조할 수 있다.
- 이번 작업의 게시 검증은 로컬 재현으로 수행했다. 실제 밴드·블로그 게시, 휴대폰 설치, 운영 서버·DB 접속은 수행하지 않았다.
