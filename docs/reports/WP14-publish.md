# WP14 발행 글 삭제와 일반 기능

2026-11-14 KST, `codex/publish-mode`, 초안 PR #17. 승인된 비공개 시험 글 한 건을 앱으로 삭제했다. 실제 삭제 클릭과 삭제 요청은 각 1회다. 새 발행·밴드·다른 글과 임시글 조작은 하지 않았다.

## 실제 확인

사전 진단을 3회 연속 통과한 뒤 공통 엔진으로 삭제 링크를 눌렀다. 이번 클릭에서 열린 고정 문구의 네이티브 삭제 확인창만 수락했다. 이후 삭제 링크는 다시 누르지 않았다.

처음에는 삭제 후 주소를 다시 열 때의 네이티브 부재 알림이 로딩 완료를 막아 `SURFACE_NAVIGATION_TIMEOUT`으로 멈췄다. 읽기 전용 복구로 해당 주소의 고정 부재 알림을 확인하고, 그 알림에는 거절로 응답했다. 목록에서도 글 번호에 해당하는 링크와 제목이 모두 없음을 확인했다. 알림만으로 삭제 완료를 판정하지 않는다.

원래 실패 기록을 `stopped / BLOG_TEST_POST_DELETED`, 빈 주소로 갱신하고 같은 기록을 다시 읽어 확인했다. 최종 설치본의 등록 기록 화면에서 “삭제함”과 시각 1건, 그 행의 삭제 버튼 0개를 확인했다. 복구 문맥은 완료 후 비웠다.

## 진단 항목

수치 진단은 1 글 한 건, 2 제목 일치, 3 URL의 글 번호·주소 일치, 4 내 글 수정·삭제 컨트롤, 5 전용 삭제 링크 한 개, 6 사각형 안정화, 7 적중 대상, 8 앱·창·입력 포커스, 9 기존 확인창 없음이다. 시험 경로만 10 제목 접두사, 11 실행 표식, 12 비공개, 13 사진 13장을 더 검사한다. 14는 진단 회차 완료, 15는 클릭 직전, 16은 삭제 확인창 일치, 17은 부재 검증 완료다. 60은 비교 전을 포함한 사각형 표본이다. 식별자 원문은 진단에 남기지 않는다.

스크롤 뒤 최소 300ms 간격으로 같은 사각형을 두 번 읽은 다음 적중 검사를 한다. 마우스를 올린 뒤에도 신원·좌표·적중·포커스·확인창을 다시 검사한다. 이번에는 사전 항목이 모두 통과했고 실제 좌표 이동은 관측하지 못했다. 종전 복합 오류의 단일 실패 항목은 재현하지 못했으므로 추정하지 않는다. 이번에 분리한 실제 실패는 16 이후의 URL 부재 확인에서 네이티브 알림을 기다리던 부분이다.

## 일반 기능과 계약

내 등록 기록의 블로그 발행 완료·저장 주소가 있는 건에 “글 삭제”가 나온다. 상품 제목, 네이버에서 삭제됨, 복구 불가를 안내하고 두 번째 명시 확인을 받는다. 내 기록을 서버에서 다시 조회하며 한 번에 한 작업만 허용한다. 임시저장·밴드·전체 기록 탭에는 삭제 동작이 없다.

일반 경로는 기록의 주소·글 번호·제목과 내 글 컨트롤을 공통 엔진으로 대조한다. 실험 표식 조건은 없다. 서버가 발행 제목을 별도로 보관하지 않으므로 상품이 변경된 기록은 명확히 거부한다. 불확실한 이전 클릭이 있으면 먼저 기록 주소의 존재 여부를 읽는다.

주소와 목록의 부재를 확인한 뒤 같은 기록을 `stopped / BLOG_POST_DELETED`, 빈 주소로 갱신하고 다시 읽는다. 화면은 “삭제함”과 서버 시각을 표시한다. 기록 실패 시에는 동일 갱신만 수동 재시도하며 사이트 삭제를 반복하지 않는다.

서버 변경은 필요 없다. 로컬 서버 소스의 본인 권한 검사, `published → stopped` 허용, 완료 시각 처리를 읽어 확인했고 계약을 명시했다. 운영 서버 코드·DB를 바꾸거나 별도 탐색 요청을 보내지 않았다. 실제 서비스에서 확인한 전이는 이번 시험 기록의 `failed → stopped`다. 일반 `published → stopped` 조합과 기록 실패 재시도는 fixture로만 확인했다.

릴리스에는 일반 기능을 포함한다. 시험 삭제 진입점·읽기 전용 복구·복구 문맥은 디버그 전용이다. 일반 기록 진입점으로 실제 다른 글을 시험하지 않았다. 공통 삭제 엔진은 이번 시험 글에서 실증했고 일반 제목·공개 글·지연 레이아웃 이동·거부·확인·재시도·화면 노출은 합성 fixture로 확인했다.

설치와 입력 전 연결·화면 켜짐·현재 창·전면 Activity를 읽어 교차 확인했다. `adb install -r`로 로그인을 유지했고 앱이 스스로 전면으로 돌아온 뒤에만 입력했다. 깨우기·잠금 해제·다른 앱 입력은 없었다.

수치 증거는 저장소 밖 `../runs/wp14-regular-attempt1.json`, `wp14-regular-check3.json`에 있다. 상품 내용·계정 식별자·글 주소·쿠키·토큰은 저장소와 보고서에 넣지 않았다.
