# WP14 비공개 발행과 일반 삭제 확인

2026-11-14 KST, `codex/publish-mode`, 초안 PR #17. 승인된 상품 한 건을 원제목·사진 13장·블로그만·발행·비공개·선택 옵션 모두 꺼짐으로 실행했다. 실제 발행 요청과 200 응답은 각 1회다. 추가 발행·밴드·다른 글 삭제는 하지 않았다.

발행 응답은 `isSuccess / result.redirectUrl` 구조였다. 값은 저장하지 않았고, 지원하지 않는 응답 필드에서 주소를 추측하지 않았다. 결과 화면 URL과 정확한 제목으로 글을 식별했다. 다만 실제 작성자 영역의 비공개 표시를 기존 선택자가 놓쳐 `BLOG_PUBLISHED_PRIVATE_UNCONFIRMED`로 멈췄다. 재발행하지 않았다.

실제 구조인 `.se-documentTitle .blog2_container .writer .desc .txt`를 추가했다. 일반 디버그 실행은 상품 원제목을 유지하고 차단 프로브만 실험 제목을 쓰도록 고쳤다. 식별 근거는 고정된 이름만 진단에 남긴다. 비공개 요청 검사와 발행 후 비공개 읽기 검사는 계속 켜져 있다.

앱 내부 복구 문맥으로 이번 주소·원제목·원래 실패 기록·상품 해시·다운로드 사진 순번을 대조했다. 발행·수정·임시저장 요청을 차단한 복구 경로에서 같은 글을 다시 읽었다. 비공개 표시, 제목, 사진 13장과 순서, 원문·숫자·해시태그가 모두 일치했다. 같은 기록을 `published`와 주소로 복구하고 서버에서 다시 읽었다. 발행 직후 자동 완료 기록은 처음에 중단됐으며, 수정 뒤 처음부터 재발행하는 실기기 시험은 하지 않았다.

일반 등록 기록의 “글 삭제”와 앱 확인·네이버 확인 두 단계를 사용했다. 1차는 결과 미확인으로 멈췄고 기록을 바꾸지 않았다. 재클릭 전에 주소를 읽어 글이 남아 있음을 확인했다. 2차는 신원·좌표·적중·포커스·확인창 검사와 주소·목록 부재 검증을 통과했다. 서버의 실제 `published → stopped / BLOG_POST_DELETED` 전이와 빈 주소를 재조회했고, 해당 시각의 “삭제함”과 삭제 버튼 부재를 확인했다. 3차 시도는 하지 않았다.

외부 관찰기의 기본 확인창 처리에서 `Page.handleJavaScriptDialog` 오류를 관측해 확인창을 앱에 맡기도록 수정했다. 1차 실패의 단일 원인은 확정하지 않는다. 일반 삭제에도 디버그 전용 수치 진단을 연결했다. 80은 주소 읽기 시작, 81은 부재 알림 확인, 90은 고정 오류 번호다. 이번 2차의 공통 검사 1~9·14~17은 모두 통과했다. 복구·추가 조회 도구와 문맥은 릴리스에서 제외되며 완료 후 문맥은 비웠다. 서버 코드 수정이나 DB 직접 연결은 없었다.
