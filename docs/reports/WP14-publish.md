# WP14 발행 방식 확인

2026-11-14 KST. `codex/publish-mode`, 초안 PR #17의 후속 작업이다. 승인 범위는 비공개 글 한 건의 발행·검증·즉시 삭제였다. 밴드와 기존 실험 임시글은 선택·수정·삭제하지 않았다.

## 결과와 소유자 조치

**발행 요청 한 번과 응답 한 번이 관측됐다. 앱의 네이버 글 화면에서 이번 실험 표식과 `WP14 private-once`, 사진 13장, 보이는 비공개 표시를 확인했다. 전체 내용 검증은 미완료이고 삭제는 실행하지 않았다. 소유자의 수동 삭제가 필요하다.**

요청 검사는 통과했지만 응답에서 글 식별을 확정하지 못해 `BLOG_PUBLISH_RESPONSE_UNCONFIRMED`로 중단했다. 제목 원문·사진 순서·숫자의 발행본 비교까지 도달하지 못했다. 응답 형식의 원인은 아직 모른다. 재발행하지 않았고, 확정된 실행 응답의 글 식별자가 없어 디버그 삭제도 누르지 않았다. API 기록은 `failed`와 위 실패 코드다. 삭제하지 않았으므로 `BLOG_TEST_POST_DELETED`는 보내지 않았다.

소유자는 현재 앱의 **‘네이버 발행 글 보기’**로 이번 글을 열고, 비공개와 실험 표식을 확인한 뒤 네이버 화면에서 직접 삭제해야 한다. ‘실험 글 삭제’는 이번 응답 식별을 확정하지 못해 사용할 수 없다. 다음 작업은 응답 구조와 수동 삭제 확인이다. 새 발행 승인을 전제로 삼지 않는다.

## 확인된 원인과 수정

첫 실행(10:15)의 검사기는 라디오 이름 `openType`만 허용했다. 실제 이름은 `open_type`이었다. 이 차이만으로 `proof.wire`가 null이 되어 차단된다. 첫 요청 원문이 없어 다른 동시 원인은 배제하지 못한다.

같은 상품으로 비공개·전체공개 프로브를 각 한 번 실행했다. 별도 `publishProbe` 플래그를 사용하며 검사 결과·선택 범위·요청 종류와 관계없이 RabbitWrite/RabbitUpdate에서 항상 false를 반환한다. 기록 실패도 차단한다. API에는 `stopped`, `BLOG_PUBLISH_PROBE_BLOCKED`를 기록한다. 작업마다 임시저장 횟수를 초기화하고 실험 표식을 구분했다.

| 구조 증거 | 비공개 프로브 | 전체공개 프로브 |
| --- | --- | --- |
| 라디오 `name` | `open_type` | `open_type` |
| 선택 라디오 `value` | `0` | `2` |
| `populationParams.configuration.openType` | 숫자 `0` | 숫자 `2` |
| 메서드·형식 | POST·URL 인코딩 | POST·URL 인코딩 |
| 인라인 본문·길이 | 있음·29,759자 | 있음·29,755자 |
| 별도 본문 조회 | 필요 없음 | 필요 없음 |
| 발행 응답 | 0건 | 0건 |

공개 범위 후보는 위 경로 하나뿐이었다. 관측 날짜를 주석에 적은 `OBSERVED_BLOG_VISIBILITY_2026_11_14`로 대응을 고정했다. 실제 라디오 상태와 관측한 필드·경로·숫자 타입이 모두 맞아야 비공개 요청을 허용한다. 중복 JSON/폼 키, 다른 경로·값·타입, 충돌하는 복사본, 알 수 없는 필드·인코딩, 깊이 초과, 불완전한 본문은 거부한다.

본문이 빠졌거나 길이가 다르면 멈춘 요청의 `networkId`로 `Network.getRequestPostData`를 호출하며 확보하지 못하면 차단한다. CDP에는 `Fetch.getRequestPostData`가 없다. 이번 두 프로브에서는 본문 누락·잘림이 관측되지 않았다.

구조 증거는 저장소 밖 `../runs/wp14-probe.json`과 비공개·전체공개 개별 파일에만 뒀다. 라디오 속성, 필드 이름·길이·JSON 여부, 깊이 8 이내 공개 범위 후보의 경로와 허용된 짧은 값만 기록한다. 상품 원문·계정/글 식별자·주소·인증 자료·원시 요청/응답은 보고서와 저장소에 남기지 않았다. 프로브 설정·기록 모듈은 디버그 전용이며 릴리스 제외 시험을 추가했다.

## 시각과 남긴 임시글

시각은 PC가 앱 알림을 받은 KST다. 세 작업 모두 같은 상품, 사진 13장, 블로그만, 선택 옵션 모두 꺼짐이다. 자동복구 안내는 매번 앱의 ‘버리고 새로 시작’으로 닫았다. 저장 뒤 새 편집기에서 원문·사진 순서·숫자 대조를 통과했다.

| 작업 | 시작 → 종료 | 임시저장 | 결과 |
| --- | --- | --- | --- |
| 비공개 프로브 | 10:35:33.533 → 10:37:27.638, 114.105초 | 10:37:11.315 | 발행 차단, 응답 0건 |
| 전체공개 프로브 | 10:38:11.988 → 10:40:04.612, 112.624초 | 10:39:48.837 | 발행 차단, 응답 0건 |
| 승인된 비공개 한 번 | 10:44:21.446 → 10:46:14.215, 112.769초 | 10:45:58.978 | 요청·응답 각 1건, 응답 식별 실패 |
| 마지막 화면 읽기 | 10:46~10:47 | 입력 없음 | 이번 표식·사진 13장·보이는 비공개·삭제 제어 확인 |

이번 프로브 임시글 두 건(10:37:11, 10:39:49)은 남겨 뒀다. 마지막 작업의 발행 전 저장(10:45:59)이 발행 뒤에도 남았는지는 중단 지시에 따라 확인하지 않았다. 이전 WP14 임시글(10:15:31)과 기존 실험 임시글 네 건은 건드리지 않았다.

설치 전 연결·power Awake·display ON·현재 창과 전면 Activity가 골투오토인지 교차 확인했다. 10:34:28과 10:43:34에 `adb install -r`로 로그인 상태를 유지했다. 설치 직후 창 전환 중에는 입력을 멈추고 조건을 다시 읽었다. 깨우기·잠금 해제·다른 앱 조작은 하지 않았다. PC 입력은 대상 적중과 포커스를 확인했으며 편집기 내용은 앱의 버튼·키보드·마우스로 입력했다. 마지막 중단 뒤 기기에 추가 입력하지 않고 이번 PC 중계만 제거했다.
