### 채널 접근 범위 — 코드 확인

릴레이는 `filesDir/devtools.sock`의 앱 전용 Unix 파일 소켓에서만 받으며 TCP를 열지 않는다.
상위 WebView는 `webview_devtools_remote_<pid>`의 Android abstract 소켓이다. UI/core HTTP는
127.0.0.1에만 listen하며 무작위 토큰·Host·Origin 검사를 유지한다. NodeRuntime의 일시적인
`ServerSocket(0)`는 포트 번호를 예약한 뒤 바로 닫으며 제어 요청을 받는 서버가 아니다.
채널 on은 앱 프로세스 수명 동안 유지하며 런타임 토글/드라이버 변경은 하지 않는다.

앱의 exported Activity는 MAIN/LAUNCHER 하나이며 Intent 명령·URL·스크립트 수신 경로가 없다.
외부 앱이 launcher로 일반 화면을 실행하면 채널도 시작되지만, 릴레이 명령이나 자동 등록을
Intent로 지시하는 경로는 없다.
FileProvider는 exported=false다. 최종 APK manifest에는 AndroidX ProfileInstallReceiver도 exported=true로
들어오지만 `android.permission.DUMP`가 필요하고 프로필 관리용이며 relay/자동 작업을 호출하지 않는다.
외부 제어용 service/receiver/deep link는 없다. 최종 APK의 aapt2 출력에서 이 구성을 확인했다.

쉽게 말하면 **앱 자체와, USB 디버깅을 켠 휴대폰에서 승인한 PC의 adb는 채널에 접근할 수 있다.**
루팅 기기의 root와 무선 디버깅으로 페어링한 PC도 접근 가능하다. 일반 다른 앱과 인터넷/LAN에
직접 열린 CDP 포트는 없다. 승인된 디버거는 앱 UI 확인과 별개로 페이지를 읽고 조작할 수 있다.
직원 설치 안내에는 USB/무선 디버깅을 끄도록 적었다. 다른 앱의 접속 거부를 실기기에서 시험하지 않았다.
근거: 앱 소켓/manifest 코드와 [Chromium peer UID 검사](https://chromium.googlesource.com/chromium/src/+/main/content/browser/android/devtools_auth.cc),
[WebView API](https://developer.android.com/reference/android/webkit/WebView#setWebContentsDebuggingEnabled(boolean)).

## Part 1 — 휴대폰과 데이터 조사

읽기 전용 dumpsys에서 켜짐·잠금 해제·앱 전면, 설치 버전 0.1.0 (1), DEBUGGABLE을 확인했다.
dumpsys package의 짧은 signatures 값은 SHA-256이 아니므로 사용하지 않았다. pm path와 adb pull로
**공개 설치 APK만** 읽고 apksigner로 인증서를 확인했다. 설치 인증서 SHA-256은
`0B36F13C248D2E5EE9A73D9088828BE4DB7D470E9ECB6E66F35432DCF80DC75E`이며 배포 키와 **DIFFERENT**다.
설치·재시작·설정 변경·로그인 확인·앱 private 데이터 읽기/쓰기·백업·삭제는 하지 않았다.
네이버 저장 0, 공개 발행 0, 실제 밴드 동작 0, 서비스 삭제 0이다.

| 데이터 | 저장 위치와 전환 영향 |
| --- | --- |
| 등록 내역 본체 | AppCore → `/auto/posts/list`, 생성/결과는 `/auto/posts/start`, `/auto/posts/update`. 계약상 서버 `gf_auto_post`. 같은 계정 재로그인 후 읽음. 운영 API/DB에는 접속하지 않아 현재 동기화 완료 여부는 미확인 |
| 공통 설정 | `/auto/me`, `/auto/settings/save`, 계약상 `gf_auto_setting`. 앱 삭제로 서버 설정이 지워지지 않음 |
| 로컬 보조 기록 | post-metadata.json의 postNo별 공개 범위·표 폴백 표시. 백업 없으면 손실 |
| 개인 옵션 | preferences.json의 선택 옵션/최근 밴드 키와 polish-strength.txt. 백업 없으면 기본값 복귀 |
| 작업 로그 | private logs 폴더. 삭제 시 손실, 기존 ‘로그 내보내기’ ZIP으로 외부 보관 가능. salt는 옮기지 않아 새 앱의 기록 연결에 재사용하지 않음 |
| 로그인 | 골투 암호화 세션과 WebView 로그인 저장소. 전환 시 소유자가 세 서비스에 직접 재로그인. 쿠키·토큰·비밀번호는 이전하지 않음 |
| 진행 중 작업·복구 | 메모리 job·debug 복구 문맥·마지막 입력 제목·미완료 편집기 상태는 이전하지 않음. 전환 전에 작업과 결과 기록을 완료해야 하며 서버 저장 실패를 자동 복구한다고 주장하지 않음 |

설정에 ‘데이터 내보내기/가져오기’를 추가했다. 사용자가 Android 문서 선택기로 파일을 고른다.
고정 세 파일의 허용 필드만 JSON으로 옮기며 폴더를 순회하지 않는다. 스키마·버전·크기·기록 키·필드를
모두 검증한 뒤 쓰고, 기존 메타데이터를 합치되 공개 범위 충돌은 쓰기 전에 거부한다. 입출력 동안
다른 명령을 잠그고 취소 시 바꾸지 않는다. 쓰기 실패는 기존 파일로 복구를 시도한다.
강제 종료/전원 손실까지 세 파일 전체의 원자성을 보장하지 않으므로 원본 백업은 보관해야 한다.
로그는 별도 ZIP 보관이며 앱으로 다시 가져오지는 않는다. 휴대폰에서 백업 UI를 실행하지 않았다.

### Part 1의 전환 제안 — 위 Part 2 절차로 대체

1. 현재 debug 앱을 유지한다. 원격 디버깅 off에서도 입력과 POST 본문·응답 통제를 보장하는 드라이버를
   먼저 검증하고 별도 기기/시험 계정에서 release 시작·연결·임시저장 재열람·로그 공유를 확인한다.
2. 별도 승인 작업에서 현재 앱과 **같은 인증서**의 백업 지원 debug APK를 WP28 게이트로 install -r
   업데이트한다. 백업 UI는 구현했지만 현재 휴대폰에는 설치하지 않았다.
3. 진행 작업·서버 기록 실패를 마치고 같은 계정의 등록 내역을 확인한다. 데이터 JSON과 로그 ZIP을
   앱 밖과 두 번째 안전한 장소에 보관하고 다른 시험 설치에서 가져오기를 대조한다.
4. 백업·서버 내역·새 release 동작이 확인된 뒤 소유자가 기존 앱 삭제가 필요한 전환 시점을 결정한다.
   삭제/재설치는 별도 명시적 승인 작업이며 이 WP에서는 실행하지 않는다.
5. 새 앱에서 세 서비스에 직접 로그인하고 서버 내역/공통 설정을 읽고 로컬 백업을 가져와 대조한다.
   로그 ZIP은 외부 보관한다. 이후 같은 배포 키로 업데이트한다.

APK는 저장소 밖 `../release-out/goltou-auto-1.0.0-2-release.apk`에 있으며 같은 이름의
`.apk.sha256` 파일을 함께 두었다. 크기는 **56,084,780 bytes**다.

서명자는 한 명, RSA 4096이며 v2/v3 검증과 공개 배포 인증서 일치를 확인했다.

최종 산출물 기준 인증서를 휴대폰과 다시 비교해 DIFFERENT를 확인했다.

설치/앱 실행 입력/데이터 변경은 0회다. 외부 요약은 `../runs/blog-shots/wp30-summary.txt`,
완료 게이트 로그는 같은 폴더의 `wp30-release-gate-verified.log`다.

호환성 검사는 실제 APK의 구문과 알려진 ICU 없는 Node 정규식 비호환을 차단한다.
휴대폰 내장 VM의 모든 기능을 실행한 시험으로 보지 않는다.

초기 자산 시험은 공통 라이브러리 고정 사유까지 제거돼야 한다는 잘못된 단언으로 실패했다.
release에 파일 구현이 주입되지 않는 검사로 고친 뒤 자산 시험은 통과했다.
기본 apksigner 검증은 minSdk 30에서 v3를 쓰며 존재하는 v2를 건너뛰어 false로 표시했다.
실제 APK를 `--min-sdk-version 24`로 검증해 v2/v3 모두 true임을 확인했고 검사기에 이 범위를
명시했다. 앱의 실제 minSdk 30은 바꾸지 않았다. 해당 인자 누락을 거부하는 회귀시험을 추가했다.
수정 전 VerifyOnly 게이트는 전체 시험 도중 중단했으며 통과 증거로 세지 않는다.
후속 스키마 감사에서 다듬기 수준을 배열에서 문자열로 강제 변환하면 통과할 수 있던 부분과
기존/이전 메타데이터 합산 후 내보내기 크기를 넘을 수 있던 부분을 보강했다. 잘못된 형식과
합산 크기는 쓰기 전에 거부한다. 이 변경 전의 두 번째 전체 게이트도 중단했고 최종 커밋에서 다시 실행한다.

실기기 release 설치·부팅·임시저장·발행·문서 선택기 백업/복원은 미검증이다.
