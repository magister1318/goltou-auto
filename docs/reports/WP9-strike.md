# WP9 취소선 글자 제외 보고서

- 작업일: 2026-11-13, KST.
- 지시: 소유자의 2026-11-13 취소선 제외 결정과 이번 작업 요청. `AGENTS.md`, `docs/PRD.md`, `docs/reports/WP4.md`, `docs/reports/WP8.md`의 취소선 지표를 읽었다.
- `GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`와 `gh` 자격 증명 도우미를 지정해 `origin`을 가져왔다. 작업 트리가 깨끗한 것을 확인하고 최신 `origin/main`의 `6c36263`에서 `codex/strike-text`를 만들었다.

## 결정과 구현

밴드가 취소선을 표시하지 못해 지난 가격·날짜가 유효한 정보로 보일 수 있으므로, 상품 본문의 취소선 글자는 블로그·밴드 모두에 옮기지 않는다. 이 필수 규칙을 PRD의 확정 결정에 추가했다. WP8의 기존 관측 자료와 당시 정책 기록은 이력으로 보존했다.

1. 변환기는 `del`, `s`, `strike`와 인라인 `text-decoration` / `text-decoration-line` 값의 `line-through`를 인식한다. 먼저 본문 트리를 순회해 중첩·표·행·셀의 취소선을 하위 텍스트에 적용하고, 글자를 뺀 뒤 기존 블록을 만든다. 취소선 안의 사진은 원래 위치와 순서에 남긴다. 제외 영역의 줄바꿈·글자 구분선도 출력하지 않는다.
2. 글자가 빠져 빈 문단은 만들지 않는다. 제거 지점 양쪽에서 새로 맞닿은 일반 공백만 합치고, 다른 인라인 요소 경계의 기존 공백은 유지한다. 남은 굵게·링크 서식도 보존한다. 제거 기록에는 사유·태그·위치만 남기며 제외한 글자를 담지 않는다.
3. `verify/source.ts`는 원본 HTML을 별도로 순회하며 자체 태그·스타일 판단으로 취소선 텍스트를 제외한다. 변환기의 판별 함수·필터 결과·제거 기록을 가져다 쓰지 않는다. 글자·표 셀·사진·배치 순서의 독립 대조를 유지하며, 잘못된 변환기가 취소선 글자를 남겨도 `sourceText`·`sourceOrder` 불일치로 차단한다.
4. 본문 숫자 보존 지표는 취소선 텍스트가 빠진 독립 원문과 실제 입력 계획을 비교한다. API 가격·출발일 배열 대조는 그대로 유지한다. 본문에서 API와 같은 가격·날짜가 취소선으로 지워져도 API 표의 값은 남는다.
5. 준비 결과의 `droppedStruckCharacters`를 두 채널 확인 화면에 전달한다. 0보다 클 때 접힌 미리보기에서도 `취소선 글자 N자는 옮기지 않습니다`를 평문 한 줄로 표시한다. 제외한 내용이나 해제 옵션은 표시하지 않으며 실제 등록 본문에는 안내를 넣지 않는다. 선택 옵션 변경·문단 되돌리기 후에도 제외 정책과 개수는 유지한다.
6. 변환 점검은 기존 `struckNumericCharacters`와 나머지 지표를 유지하고 `droppedStruckCharacters`를 추가했다. 취소선 숫자 지표도 인라인 스타일을 포함한다. 제거 글자 수는 HTML 엔티티를 해석한 원본 텍스트의 유니코드 코드포인트 수이며 공백을 포함하고 중첩은 한 번만 센다. 속성·스크립트 등 기존 제외 영역은 세지 않는다. 점검 결과에는 개수만 기록한다.

## 시험 범위

- 코어 회귀 시험 21개: 세 태그, 중첩, 두 스타일 속성, 대소문자·복합 장식·하위 `none`, 취소선 숫자·가격·날짜, 완전히 빈 문단과 일부만 빠진 문단, 제거 지점 공백과 기존 공백 구별, 굵게·링크, 취소선 안 사진, 표·행·셀의 취소선, 엔티티·보충 평면 문자·중첩 개수, 제외 코드 미집계, API 사실 보존, 잘못된 변환기 독립 차단, 선택형 다듬기·되돌리기 이후 정책 유지를 확인한다.
- UI 회귀 시험 3개: 블로그·밴드의 접힌 미리보기에 개수 안내가 한 번만 나오고 제외 글자·해제 조작이 없으며, 제외 개수가 0이면 안내가 없음을 확인한다.
- 기존 숫자 취소선 시험은 원래 숫자 13자 지표를 유지하면서 총 제거 24자와 두 채널 숫자 보존을 확인하도록 갱신했다. 등록 실행기 시험 자료 2곳에는 새 필수 개수 필드의 0을 추가했다.
- 최초 집중 시험에서 예상 제거 글자 수를 잘못 적은 1건과 타입 검사에서 빠진 시험 자료 필드 2곳을 고쳤다. 코드 검토에서 공백 정리 범위를 제거 경계 한 곳으로 좁히고 기존 공백 보존 회귀 시험을 추가했다. 최종 결과는 아래 확인 명령에 기록한다.
