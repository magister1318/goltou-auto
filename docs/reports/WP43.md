# WP43 밴드 게시 후 사진 재확인

## 원인과 수정

- 제보된 `postContent > div.uWidget.-expanded > ul.uCollage > li.collageItem > div.collageImage > img` 구조를 같은 합성 페이지에서 비교했다. `722ffc2`는 사진을 0장, 수정본은 31장 읽었다. 제보된 0장 판독과 일치한다.
- 게시 상세 화면의 읽기 응답에서 밴드와 게시물 번호를 대조한다. `photo_count`와 `attachment.photo` 배열 길이가 일치하면 첨부 경로 순서를 작성기에서 확인한 업로드 순서와 비교한다. 콜라주에 보이는 사진은 전체 첨부 목록에서 같은 상대 순서에 있어야 한다. 짧은 피드 미리보기만 얻으면 누락 판정을 보류한다.
- 확인된 사진이 65장이면 게시 주소와 함께 ‘사진 66장 중 65장 게시 확인 · 1장 누락’을 표시한다. 수량이 맞고 순서가 다르면 ‘사진 순서 확인 필요’를 표시한다.
- 밴드 확인 대기와 상세 판독 등 반복 이벤트를 전송 시 집계한다. 횟수, 합계·최대 시간과 수치가 있는 이벤트의 첫 값·끝 값을 남긴다. 실패와 게시 결과는 개별 이벤트로 보존한다. 실제 post 67 전송 로그의 원본은 확보하지 못해 어떤 이벤트가 512KB를 채웠는지는 추정이다.
- 앱 버전은 1.1.0 (14)이다.

## 검증과 다음 확인

- 31장 콜라주를 포함한 합성 게시 상세에서 API 사진 66장과 65장을 각각 재현했다. 두 경우 모두 게시 주소를 보존했고, 66장은 확인 완료, 65장은 1장 누락으로 기록했다. 각 작업의 전송 로그는 64,000바이트 미만이었다.
- 같은 합성 원본 로그에 이전 압축과 새 압축을 각각 적용했다. 66장 확인 작업은 436,863바이트에서 47,323바이트로, 65장 확인 작업은 437,116바이트에서 47,572바이트로 줄었다. 기기용 원본 JSONL의 기록 방식은 유지한다.
- `pnpm install --frozen-lockfile`, `pnpm typecheck`, `node scripts/check-embedded-compat.mjs --sources`(110개), `pnpm build`와 Android `gradlew.bat assembleDebug`가 통과했다.
- `pnpm test --maxWorkers=4` 전체 시험은 109개 파일의 1,340개가 통과했다. `scripts/check-test-report.mjs`에서 필수 런타임 시험 6개를 포함하고 건너뜀과 TODO가 각각 0개임을 확인했다. `pnpm check:secrets`와 Git 변경 검사를 통과했다.
- 실제 게시 및 휴대폰 조작 없이 로컬에서 검증했다. 다음 실기기 확인에서는 같은 밴드의 게시 상세가 반환하는 사진 수·경로를 판독할 수 있는지와 실제 전송 로그 크기를 확인한다.
