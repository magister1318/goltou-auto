# WP48 블로그 태그 창 재열기 오류 수정

## 원인과 변경

- 11월 20일 S24의 1.1.4(18)에서 확인한 조건을 재현했다. 13개 칩을 읽으려고 태그 창을 다시 열면 `clientHeight=71`, `scrollHeight=156`, `scrollTop=0`이었고, 가려진 입력칸의 중심은 `DIV.set_option_detail`에 닿았다. 클릭 보호가 `BLOG_TAG_FOCUS_LOST`로 막았고, 닫기에서도 같은 위치를 클릭하려다 `BLOG_TAG_LAYER_NOT_CLOSED`가 났다.
- 첫 태그 입력, `observe()`의 다시 읽기, `closeTagLayer()`에 공통 클릭 함수를 적용했다. 입력칸 중심이 보이는 영역 안에 있고 실제로 입력칸에 닿는지 확인한다. 가려졌으면 태그 상자 자체에 닿는 지점을 우선 사용하고, 필요하면 상자 안의 자식 요소에 닿는 지점을 사용한다. 상자에 남은 스크롤 범위 안에서 CDP `mouseWheel`을 최대 8회 보내고 매회 위치를 다시 읽는다. 실제 클릭 직전 대상을 재확인하고 클릭 후 입력칸 포커스를 확인한다.
- `verification` 결정 줄에 태그 상자 높이, 스크롤 위치, 칩 개수, 입력칸 중심의 가시 영역 여부, 맞은 요소 이름, 휠 횟수를 넣었다. 보호기는 클릭·키·입력을 차단할 때 검사 위치와 포인터 대상 또는 포커스 요소 이름을 기록한다. 로컬과 WP46 전송본에는 고정 태그명과 허용 클래스 접두어만 담는다.
- Android 버전을 1.1.4(19)로 올렸다. 소스 기준은 `codex/v114`의 WP47 `ec3b85f`다.

## 합성 로그 예시

```jsonl

{"step":"verification","event":"decision","choice":"fail","check":"focus","reason":"BLOG_TAG_FOCUS_LOST","blogTag":{"phase":"input_after","hit":"BUTTON"}}
```

## 검증

- 수정 전 WP47 코드에 새 합성 편집기와 시험을 적용했다. 13개와 30개는 `BLOG_TAG_LAYER_NOT_CLOSED`로 실패했고 2개는 통과했다.
- 수정 후 13개, 30개, 2개에서 첫 입력과 `observe()`의 정확한 태그 판독, 직접 닫기, 저장 후 다시 읽기, 로컬 합성 발행과 결과 판독을 모두 확인했다. 13개와 30개에서는 실제 휠이 태그 상자에 닿았고, 2개에서는 휠 입력이 0회였다. 세 경우 모두 태그 창이 열린 동안 본문 스크롤은 0회였다. 휠이 진행되지 않는 합성 조건에서는 8회에 멈추고 창이 열린 상태로 실패하는 것을 확인했다.
- `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm check:secrets`, `git diff --check`를 통과했다.
- Node 18.20.4에서 새 회귀와 입력 보호·업로드 허용 목록 시험 8개를 통과했다. 내장 런타임 실행 소스 116개와 디버그 APK 내부 번들 2개의 호환 검사도 통과했다.
- Android `gradlew.bat :buildSrc:test testDebugUnitTest testReleaseUnitTest assembleDebug --console=plain --offline`을 통과했다. buildSrc 10개, Debug 및 Release 단위 시험 각 23개에서 실패와 건너뜀은 0개였다. 디버그 APK의 `kr.goltou.auto`, 버전 1.1.4, versionCode 19와 내장 번들 소스 커밋을 확인했다.
- 전체 `pnpm test`에서 110개 파일의 1,368개 시험이 모두 통과했다. 필수 런타임 시험 6개, 건너뜀 0개, TODO 0개를 JSON 결과로 확인했다.
- `pnpm build`와 WP47에서 사용한 `./scripts/install-device.ps1 -Variant release -VerifyOnly -ArtifactDirectory ../release-out`을 통과했다. 릴리스 APK의 패키지·버전·소스 커밋, v2·v3 서명, SHA-256 파일의 일치를 확인했다. 내장 번들 2개는 Node 18.20.4에서 다시 검사했다.
