# WP19 run 8: 밴드 시험 글 삭제 완료

**시험 글은 삭제됐다. 새 글 생성·재제출은 0회다.**

2026-11-17 01:20 KST에 기존 `codex/band-real-test` 브랜치에서 시작했다. 최초 확인에서는 글이 실제로 남아 있었다. 앱의 등록 기록 → 글 삭제 → 삭제 확인으로만 진행했으며, 01:30:38 KST 단일 삭제 요청 한 건이 HTTP 200과 성공 코드를 받았다. 이후 원래 주소의 삭제 안내와 피드 부재를 확인하고, 01:47:58 KST 원래 기록 한 건을 `BAND_POST_ALREADY_DELETED`로 정리했다.

## 대상과 실제 결과

- 최초 새 피드 응답에서 원래 기록의 주소·제목·정규화 본문 해시·본인 글 여부·원래 생성 시각이 모두 일치했다. 소유자가 23:40으로 지칭한 글의 원래 수신 시각은 2026-11-16 23:39:58 KST다.
- 앱 삭제 시작은 총 13회다. 첫 회는 기존 검사에서 차단됐고, 두 번째 회에서 서비스 삭제 한 건이 성공했다. 나머지 11회는 이미 없는 글을 먼저 확인하는 읽기와 기록 정리 경로였다. 추가 삭제를 무장하거나 전송하지 않았다.
- 삭제 후 피드를 두 번 새로 읽었다. 최종 읽기 전용 피드도 로드 완료, 글 카드 20개, 시험 제목·시험 글 카드 0개, 작성기 없음이었다.
- 저장된 원래 글 주소에서 동일 글에 묶인 두 GET 읽기만 수행했다. 읽기 응답의 오류와 같은 주소에서 열린 삭제 안내 alert를 함께 확인했다. alert의 원문이나 인증 값은 로그에 남기지 않았다.
- 원래 등록 기록을 다시 읽어 `stopped`, `BAND_POST_ALREADY_DELETED`, 주소 비움을 확인했다. 화면은 “밴드에서 이미 삭제됨”이고 그 행의 글 보기·삭제 버튼은 모두 없다.
- 중간에 서비스 삭제는 성공했으나 주소 검증이 끝나지 않았을 때는 기록을 성공으로 바꾸지 않았다. 이후의 읽기 재확인에서 이미 삭제된 상태로 정리했다. 두 번째 삭제 성공으로 세지 않는다.

## 차단 원인과 좁은 수정

기존 삭제 검사에 이유 로그를 먼저 추가한 뒤 같은 앱 경로로 확인했다. 기록된 거절 코드는 `QUERY_BLOCKED`였다. 요청 본문이나 인증 값을 출력하지 않고 다음 형태만 기록했다.

| 항목 | 관측한 형태 |
| --- | --- |
| 메서드 | POST |
| 호스트 | api-kr.band.us |
| 경로 | /v1.5.0/delete_post |
| Content-Type | application/x-www-form-urlencoded |
| 쿼리 이름 순서 | version, ts |
| 본문 필드 이름 순서 | band_no, post_no |

기존 검사는 시각 필드 `ts`를 모르는 쿼리로 거절했다. 13자리 숫자 `ts` 한 개만 추가 허용했다. 실제 주소·번호·본문·인증 값은 회귀시험에 복사하지 않았다.

앱 확인을 소비한 뒤 서비스 삭제 확인 직전까지만 무장하고, 저장된 대상에 대한 완전한 POST 한 건만 통과시킨다. 다른 글·밴드·댓글·일괄 경로·추가 대상 필드·중복 키·잘못된 메서드·중복 요청은 차단한다. 삭제 경로의 GET도 일반 읽기 허용으로 통과하지 않도록 했다.

## 본문·시각 검증과 삭제 후 읽기

- 바뀌지 않은 상품으로 기본 옵션 본문을 다시 구성하고 SHA-256을 비교한다. 기록 시각 범위를 벗어난 글은 입력 전에 거절한다. 처음 읽은 정확한 생성 시각과 본문을 고정해 이후 조작에서도 재검사한다.
- 본문·제목·소유·주소·시각 중 하나라도 맞지 않으면 삭제를 시작하지 않는다. 옵션이나 변경 때문에 본문을 재현하지 못하는 기록도 추정해서 삭제하지 않는다.
- 피드에서 빠졌다는 이유만으로 완료하지 않는다. 원래 주소에 글이 남아 있으면 이미 삭제됨으로 기록하지 않는다.
- 주소 검증에는 데스크톱 문서 읽기와 동일 글에 한정된 읽기 묶음을 사용한다. 실제 삭제 안내 문구와 native alert가 DOM 읽기 사이에 열리는 경우를 처리했다. 인증·접근 실패나 다른 주소의 안내를 삭제로 받아들이지 않는다.
- 고정 이유 코드, 허용한 필드 이름, 검사 참·거짓만 앱 전용 파일에 순서대로 남긴다. 앱 확인·대상 검증·메뉴·서비스 확인·요청 허용/거절·응답·재읽기·기록 저장을 추적할 수 있다.

피드 확인 화면은 디버그 빌드의 검증 후 보기다. 같은 밴드 프로필과 허용된 정확한 피드 경로만 사용하고, native shell이 터치와 포커스를 차단한다. 서비스 메뉴나 삭제를 진단 스크립트로 누르지 않았다. 읽기 전용 보기에서 앱으로 돌아오는 native 버튼만 눌렀다.

휴대폰은 깨어 있고 잠금 해제·앱 전면 상태였다. 깨우기·잠금 해제·설정 변경·다른 앱 입력을 하지 않았다. 설치는 `adb install -r`만 사용했다. 새 허용 파일·생성 제출·네이버 조작·로그인 페이지 입력은 없었다. 다른 게시글이나 댓글을 수정·삭제하지 않았다.
