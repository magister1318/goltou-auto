# WP19 다섯 번째 실밴드 시험과 대상 필드 수정

## 결과

2026-11-16 23:00 KST 소유자 진행 지시에 따라 기존 작업 브랜치와 초안 PR #23에서 진행했다. 이번 실행의 실제 제출 클릭은 **1회**, 생성 성공은 **0건**이다. 이전 두 차단된 클릭과 구분한다.

23:08:59 KST 첫 제출에서 앱이 `BAND_POST_BLOCKED:TARGET_MISSING`과 `BLOCK_CONFIRMED`를 기록했다. `publicationUncertain`은 false였다. 제출 전·차단 후·수정 APK 교체 설치 후에 앱의 게시용 BandDirectory WebView로 승인된 피드를 다시 읽었고 시험 제목은 없었다. 로그인 확인용 WebView로 피드를 열지 않았다.

서로 충돌하는 ‘조건 충족 시 최대 두 번’과 ‘총 한 번’ 지시에 대해 확인을 요청했다. 답변 전에는 엄격한 한 번 한도를 적용했다. 두 번째 허용 파일이나 제출은 하지 않았다.

## 실기기에서 확인한 범위

- 휴대폰이 깨어 있고 잠금 해제 상태이며 앱이 전면임을 읽기 전용으로 확인했다. 화면 깨우기·잠금 해제·기기 설정 변경·다른 앱 조작을 하지 않았다.
- 이전 승인 상품과 같은 본문인지 앱 미리보기에서 비교했다. 밴드만 선택하고 블로그는 해제했다. 승인 항목의 정확한 접미사와 선택 상태를 확인했고 다른 밴드는 선택하지 않았다. 문장 다듬기·글 끝 문구·링크 카드는 모두 꺼짐이었다.
- 앱의 정상 입력 흐름으로 2,981개 코드 포인트와 사진 29장이 입력됐다. 문구를 추가하거나 바꾸지 않았다.
- 제출 직전 일회성 허용 파일을 정확히 한 번 만들었다. 앱이 실제 서비스 클릭 직전에 소비했고 다시 만들지 않았다.
- 제출 전에 읽기 전용 CDP 관찰을 연결하고 실제 읽기 요청의 기록을 확인했다. 요청 메서드·호스트·경로·Content-Type·본문 필드 이름·순서만 외부 파일에 기록했다. 요청 값·쿠키·토큰·자격증명은 기록하지 않았다. 앱 전용 사유 코드 로그도 계속 외부로 보존했다.
- 차단 뒤 피드는 로드 완료, 작성기 없음, 기존 글 옵션 20개, 글쓰기 버튼 있음, 시험 제목 없음이었다. 새 글 식별값이나 저장된 새 글 주소가 없으므로 삭제를 시도하지 않았고 등록 기록을 삭제 완료로 바꾸지 않았다.

## 원인과 수정

실제 생성 요청은 공개 서비스의 `/v2.0.2/create_post`에 보내는 `application/x-www-form-urlencoded` 요청이었다. 대상 필드 이름은 `band_no`였고 `band_key`는 없었다. 기존 차단기는 `band_key`만 검사해 `TARGET_MISSING`으로 거절했다. 이번 거절의 원인을 사유 코드와 실제 요청 형태로 입증했다. 과거 두 번의 개별 거절 사유까지 소급 확정하지는 않는다.

`band_no`는 관측된 정확한 HTTPS 출처·생성 경로·폼 인코딩에서만 허용한다. 선택한 대상과의 값 일치, 본문 완전성, 승인 상태, 일회성 전송 검사는 유지한다. 두 대상 필드의 혼용과 중복은 거절하며 다른 경로·인코딩에서 이 별칭을 허용하지 않는다. 생성 경로나 출처 허용 범위를 넓히지 않았다.

실제 요청의 최상위 필드 이름과 사진 업로드 29회 후 생성 순서를 이용한 회귀시험을 추가했다. 모든 대상·본문·사진 주소와 값은 합성이다. 운영 서비스에 연결하지 않는 루프백 CDP 서버에서 실제 CdpSurface와 BandDirectory 코드를 실행한다.

- 수정 전: 같은 형태의 폼이 차단되는 결함을 재현했다. 초기 시험 작성 문법 오류는 고친 뒤 결함 재현 결과와 구분해 외부 로그에 남겼다.
- 수정 후 집중 실행: 31개 통과, 실패 0, 건너뜀 0. 인라인 본문과 Network 본문 복구 모두 정확히 한 생성만 통과한다.
- 잘못된 대상, 대상 중복·혼용, 다른 인코딩·경로, 승인 전·기전송 뒤 요청은 차단한다. 거절 후 편집기 재시도도 승인하지 않는다.

## 확인하지 못한 것과 다음 작업

실제 게시 성공·실서비스 응답의 새 글 식별값·등록 기록의 게시 완료·앱 내 삭제는 확인하지 못했다. 삭제 선택자 수정 회차와 삭제 시도는 모두 0회다. 게시된 글이 없어 실제 줄바꿈, 사진 순서·배치, 해시태그, 링크 클릭 가능 여부, 잘림과 미리보기 차이도 확인하지 못했다. 미리보기는 수정하지 않았다.

APK에 대상 필드 수정과 사유 로그 코드가 포함됨을 확인했다. 실제 요청 형태 점검에서도 생성 요청 1개, 선행 사진 업로드 29개, 회귀시험의 최상위 필드 이름/순서 일치, 요청 값 저장 없음이 확인됐다.

새 캡처는 외부 `f-*.png`, 요청 형태와 사유 코드는 외부 `f-request-shapes.jsonl` 및 `f-barrier-codes.json`에 보관한다. 기존 증거를 보존하고 `summary.txt`를 진행 중 갱신했다. 게시·삭제가 없으므로 해당 성공 캡처를 만들지 않았다. 실제 밴드 이름·게시글 주소/번호·계정 이름·상품 문구는 보고서·커밋·PR에 포함하지 않는다.

다음 실제 제출은 한도 충돌이 해소된 승인 범위에서만 진행해야 한다. 이후 성공하더라도 실제 피드의 내용과 앱에 저장된 글 식별값/주소가 일치함을 확인한 뒤 앱의 등록 기록 삭제 기능으로 해당 한 건만 삭제해야 한다. 이번 수정의 실서비스 통과나 삭제 성공을 주장하지 않는다.
