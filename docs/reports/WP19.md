2026-11-16 20:08 KST 소유자의 이번 작업 승인 범위에서 진행했다. 기존 브랜치 `codex/band-real-test`, 기준 `f2406af`를 유지했다. 처음 읽기 점검에서 기기는 켜짐·잠금 해제·앱 전면 상태였다. 기기를 깨우거나 잠금을 풀거나 설정을 바꾸지 않았다. 앱 밖 화면이나 로그인 화면을 열지 않았고 네이버 블로그를 조작하지 않았다.

## 제출 제한과 관측

- 이전 실행의 제출 0회와 허용 파일 부재를 먼저 확인했다. 앱 발행 시작 직전에 허용 파일을 한 번 만들었다.
- 첫 실행은 사진 첫 장 업로드가 차단돼 게시 전에 멈췄다. 허용 파일이 남아 있었고, 앱에서 작성 취소 후 읽은 피드에도 시험 글이 없었다. 코드 수정과 재설치 뒤 재시작했다.
- 재설치 뒤 글쓰기 화면 열기 두 번이 실패했다. 작성기·게시물 생성과 허용 파일 소비는 없었다. 원인은 확정하지 못했으며 다음 재설치 뒤 정상 입력됐다. 앱 발행 시작은 총 3회였지만 서비스 게시 버튼은 마지막 실행에서만 눌렀다.
- 게시 전 본문은 계획과 일치했다. 29장을 한 장씩 첨부한 순서 증거 `[1..29]`가 확인됐다. 편집기 썸네일은 모두 75×75여서 원본 비율 대조는 `unavailable`이었다.
- 20:53:11 KST 앱이 실제 게시 버튼을 1회 눌렀고 허용 파일을 소비했다. 이후 허용 파일을 다시 만들거나 게시를 재시도하지 않았다.
- 앱은 `BAND_POST_UNCONFIRMED`로 멈췄다. 읽기 전용 네트워크 오류 관측에서 실제 `/v2.0.2/create_post` 요청이 `BlockedByClient`로 차단된 것을 확인했다. 작성기에는 본문과 사진이 남아 있었다.
- 같은 앱 WebView에서 해당 밴드 피드를 새로 열어 확인했다. 로드 완료, 작성기 없음, 글쓰기 버튼 표시, 게시글 옵션 20개가 보였고 시험 글 제목은 없었다.
- 생성된 글 식별값·주소가 없으므로 삭제를 누르지 않았다. 다른 글·댓글을 삭제하거나 편집하지 않았다. 삭제 수정 라운드도 0회다.
- 등록 기록은 정직하게 **밴드 확인 필요** 상태로 남겼다. 삭제 완료로 바꾸지 않았다.

## 변경

- 실제 사진 업로드의 정확한 HTTPS 호스트·경로를 허용했다. 수정 뒤 실기기에서 29장 첨부와 순서 검증까지 진행됐다.
- 모바일 작성기 헤더의 완료 버튼을 좁은 선택자로 찾도록 했다. 피드의 글쓰기 버튼과 구분하며 동일 실행의 두 번째 게시를 막는 기존 검사를 유지했다.
- 관측된 생성 경로를 기존 1회 요청 차단·대상 키 확인·응답 식별값 확인에 연결했다. 이 수정은 실제 제출 후에 했으며 **실서비스에 재제출해 확인하지 않았다**. 실제 요청 필드와 응답 형식은 아직 검증되지 않았다.
- JSON·폼 요청의 다른 대상, 불완전한 본문, 다른 버전·호스트·경로와 두 번째 요청을 거부하는 합성 시험을 추가했다.
- 알려진 전송 시간 초과만 고정 진단 코드로 구분한다. 임의 오류 문구나 상품·주소를 진단 코드에 넣지 않는다.
- 미리보기와 삭제 선택자는 바꾸지 않았다.

## 실제 외형과 증거

게시된 글이 없어 본문 줄바꿈, 사진 배치·순서·총수, 해시태그 변환, 링크 클릭 가능 여부, 접힘·잘림을 관측하지 못했다. 편집기 입력 성공을 게시 후 외형 성공으로 간주하지 않는다. 미리보기의 본문과 29개 사진 자리만 확인했으며 실제 게시 외형과의 차이는 다음 검증으로 남긴다.

실제 상품·계정·밴드 정보와 모든 원시 증거는 저장소 밖 `../runs/band-shots/`에만 있다. 이전 파일을 보존하고 `summary.txt`를 갱신했다. `d-preview.png`는 게시 전 밴드 탭, `d-result.png`는 결과 미확인 화면, `d-history.png`는 확인 필요 기록이다. 게시·삭제된 글이 없으므로 `d-posted-*.png`, `d-deleted.png`를 성공 증거처럼 만들지 않았다. CDP 화면 캡처 시간 초과는 앱 전면 상태를 확인한 뒤 읽기 전용 기기 캡처로 대체했다.
